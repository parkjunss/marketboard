# 자동 모의 매매 v1

## General — 목적과 범위

사용자가 전략을 설정하면 서버가 자동으로 모의 매매를 진행하고, 왜 거래했는지와 거래하지 않았는지를 기록한다. 실제 증권사 API·실시간 시세 API는 연결하지 않는다.

`/execution`은 고정 합성 가격의 주문 장애 검증실로 유지하고, `/auto-trading`은 DB에 저장된 일별 가격을 시간순으로 진행하는 자동 모의 매매 화면으로 제공한다. 한 번에 결과만 계산하는 기존 백테스트와 달리 실행 위치·상태·매 거래일 기록을 DB에 남겨 일시정지와 재개가 가능하다.

이번 버전은 단일 종목의 이동평균 추세 전략이다. 이름 붙인 전략 보관과 설정 복제, 동일 가격 사본 재실행 및 실행 간 비교를 제공한다. 다른 전략 알고리즘, 다종목 배분, 실시간 시장 관찰, 임의 전략 코드 업로드는 포함하지 않는다.

## Function — 사용자 흐름

1. 로그인 후 **자동 모의 매매** 메뉴를 연다.
2. DB에 일별 가격이 있는 종목과 기간을 선택한다.
3. 이동평균 거래일 수, 초기 자금, 주문 금액 한도, 최대 매수 비중, 수수료, 슬리피지, 진행 간격을 설정한다.
4. **전략 저장하고 자동 시작**을 누르면 설정과 가격 사본을 고정하고 자동 실행을 시작한다.
5. 화면을 닫아도 서버가 켜져 있으면 계속 진행한다. 화면은 3초마다 저장된 상태를 조회한다.
6. 매매 일지에서 거래일, 실제 저장 시각, 신호일·종가·이동평균, 판단 근거, 체결 수량·가격·비용·잔고를 확인한다. 매수·매도만 필터링할 수 있다.
7. 일시정지 후 같은 위치에서 재개하거나, **실행 종료**로 기록을 남기고 끝낸다. 종료·완료된 실행은 재개하지 않으며 새 실행을 만든다.
8. **저장 기록 재생 검증**으로 고정 가격과 설정을 다시 계산해 잔고 및 전체 일지를 비교한다.

## Spec — 전략 및 체결 규칙

- 버전: `sma-paper-v1`.
- 현재 거래일 t의 신호는 t 이전의 종가만 사용한다. 전일 종가와 전일까지 N개 종가의 단순 평균을 비교한다.
- 전일 종가 > SMA이고 미보유이면 매수한다. 전일 종가 < SMA이고 보유 중이면 매도한다. 같거나 이미 보유한 상승 구간이면 관망한다.
- N개 거래일이 쌓이기 전에는 `HOLD`와 준비 기간 사유를 기록한다.
- 신호가 나온 다음 거래일의 시가에 체결한다. 매수 가격은 시가 × (1 + 슬리피지), 매도 가격은 시가 × (1 - 슬리피지)다.
- 1bp는 0.01%다. 수수료는 체결 금액에 곱해 매수 시 현금에서 차감하고 매도 시 대금에서 차감한다.
- 현금·최대 비중·1회 주문 한도를 만족하는 0.0001주 단위로 계산한다. 공매도와 차입은 없다.
- 매도에도 주문 한도를 적용한다. 따라서 상승한 보유분은 한 번에 전량 매도되지 않을 수 있으며, 다음 하락 신호에서 잔량을 다시 매도한다.
- 매수 시 비중을 제한하며, 보유 중 가격 상승으로 비중이 증가했다고 자동 재조정하지 않는다.
- 종료일에는 강제 청산하지 않는다. 최종 평가금액에는 종가 기준 미실현 손익이 포함된다. 배당·분할 및 수정주가 보정 여부가 확인되지 않았으므로 성과 연구의 근거로 확대 해석하지 않는다.
- 초기 자금 1~100,000,000 USD, 이동평균 2~200일, 비용 각각 0~100bp, 진행 간격 2~300초. 실행당 최대 1,000개 가격이며 N+1개 이상 필요하다. 현재 UTC 날짜보다 이전의 완료된 날짜만 허용한다.
- 진행 간격은 과거 1거래일을 처리한 뒤 다음 거래일 처리까지 기다리는 시간이다. 실제 시장 시간과 같지 않다.

## 저장·실행 경계

- Python `auto_trading.py`: Decimal 기반의 유일한 금융 계산 주체. 외부 네트워크와 DB를 사용하지 않는다.
- Spring `AutoTradingService`: 사용자 소유권, 설정·가격 스냅샷, 실행 상태·위치, 일지와 제어 이력의 영속화.
- V42: `auto_trading_runs`, `auto_trading_journal`, `auto_trading_controls`.
- 생성 요청은 사용자별 Idempotency-Key로 중복 방지한다. 다른 설정을 같은 키로 보내면 거부한다.
- 실행 행에 `FOR UPDATE`를 걸고 다음 실행 시각과 상태를 재확인한 뒤 한 거래일만 처리한다. 일지의 `(run_id, step_number)`는 유일하며 잔고·위치·일지를 같은 트랜잭션에 커밋한다.
- 1초 주기의 스케줄러가 실행 시각이 지난 작업을 찾는다. 여러 작업자가 동시에 요청해도 같은 날짜를 중복 반영하지 않는다.
- 계산 실패는 해당 트랜잭션을 롤백하고 `ERROR` 상태로 정지한다. 사용자가 서버 상태를 확인한 뒤 재개하면 저장된 다음 날짜부터 진행한다.
- 재시작 시 누락된 시간을 한 번에 건너뛰지 않는다. 기록된 위치에서 다시 한 거래일씩 진행한다.
- 실행 상태: RUNNING, PAUSED, ERROR, COMPLETED, STOPPED. 미완료 실행은 사용자당 최대 5개다.
- 가격은 생성 시 복사되며 원본 `price_history`가 이후 수정되어도 기존 실행 결과는 변하지 않는다.
- 매 틱마다 처리된 가격 prefix를 Python으로 재생한다. 최대 1,000거래일의 로컬 검증 규모에 한정한다. 대규모 운용에는 순차 상태 계산과 작업 큐의 별도 설계가 필요하다.

## API

모든 엔드포인트는 인증이 필요하며 개별 실행은 소유자만 접근한다.

| 요청 | 역할 |
|---|---|
| `GET /api/auto-trading/prices` | 저장된 종목과 가격 기간 |
| `GET /api/auto-trading` | 최근 실행 목록 |
| `POST /api/auto-trading` | 설정·가격 고정 및 자동 시작 |
| `GET /api/auto-trading/{id}` | 상태·매매 일지·제어 이력 |
| `GET /api/auto-trading/{id}/comparison` | 처리된 가격 사본으로 SMA와 매수·보유 성과 비교 |
| `POST /api/auto-trading/{id}/control` | PAUSE, RESUME, STOP |
| `POST /api/auto-trading/{id}/verify` | 저장 상태 및 일지 전체 재생 비교 |
| `GET /api/auto-trading/strategies` | 계정 소유 저장 전략 목록 |
| `POST /api/auto-trading/strategies` | 이름·sourceRunId·configuration으로 전략 별도 저장, Idempotency-Key 필수 |
| `POST /api/auto-trading/strategies/{id}/runs` | 원본 가격 사본으로 새 실행, Idempotency-Key 필수 |
| `GET /api/auto-trading/{id}/compare/{otherId}` | 같은 조건 확인 및 공통 처리일 기준 두 실행 비교 |
| `POST /api/auto-trading/strategies/{id}/validations` | 저장 전략 고정 후 조정 기간 이후의 별도 검증, Idempotency-Key 필수 |
| `GET /api/auto-trading/validations` | 계정별 기간 검증 기록 목록 |
| `GET /api/auto-trading/validations/{id}` | 고정 설정·준비 기간·양쪽 성과 및 그래프 |
| `POST /api/auto-trading/validations/{id}/verify` | 저장된 가격으로 양쪽 결과 재계산 비교 |

## 기간 분리 검증

- **기간 검증** 탭에서 저장 전략을 선택한다. 저장 전략의 원본 날짜 범위를 조정 기간으로 사용한다.
- 검증 시작일은 조정 종료일보다 반드시 뒤여야 한다. 시작일 ≤ 종료일 < 현재 UTC 날짜를 서버에서 검증한다.
- 저장 전략의 알고리즘·이동평균·자금·비중·주문 한도·비용은 변경할 수 없다. API 요청은 검증 시작일·종료일만 받는다.
- 검증은 기존 자동 실행과 별도의 동기식 계산이다. 스케줄러를 시작하지 않고 전체 기간을 한 번에 계산해 결과를 저장한다.
- 조정 성과는 저장 전략 설정으로 원본 실행의 고정 가격 전체를 재생한다. 원본 실행이 중간에 정지됐더라도 고정한 전체 조정 기간을 사용한다.
- 검증 성과는 초기 자금·보유 수량 0에서 새로 시작한다. 조정 구간의 잔고나 손익은 이어받지 않는다.
- 검증 시작일 이전의 가장 최근 N개 저장 가격을 준비 가격으로 고정한다. 준비 가격은 순서·중복·가격 범위를 검증하고, 검증 첫 거래일보다 앞서야 한다. 거래나 성과 계산에는 포함하지 않는다.
- 첫 검증일 시가에 이전 종가만 사용해 매매할 수 있다. 매수·보유 벤치마크도 첫 검증일에 같은 비용·투자 한도로 진입한다.
- 검증 가격이 없거나 준비 가격이 N개 미만이면 거부한다. 검증 가격과 준비 가격 합계는 최대 1,000개다. 거래소 달력 기반 누락 검사는 기존과 같이 수행하지 않는다.
- V44 `auto_trading_validations`는 사용자·전략·검증 날짜·요청 키·설정/가격 사본·조정/검증 결과·생성 시각을 저장한다. 최대 100개/계정이며 동일 요청 재시도는 기존 기록을 반환한다.
- 계산 실패는 부분 기록 없이 롤백한다. 원본 `price_history`가 변경·삭제돼도 저장 검증은 재계산 가능하다.
- 서로 다른 기간의 누적 수익률·낙폭·거래 횟수를 보여주며 자동 합격/불합격이나 수익성 판단은 하지 않는다. 조정 구간의 초기 SMA 준비 기간은 현금 보유로 포함되고, 검증 구간의 준비 가격은 성과에서 제외된다.
- 이는 날짜·설정 분리를 보장하는 기능이다. 사용자가 과거에 검증 구간을 보지 않았음을 보장하지 않는다. 반복 검증 기록을 남기고, 같은 구간을 보고 설정을 조정하면 더 이상 독립 검증이 아니라는 점을 화면에 표시한다.

## 전략 보관·복제·재실행

1. 기존 실행을 선택해 **선택 실행의 전략 저장하기**를 누른다. 실행이 없으면 기존 전략 설정 폼에서 첫 실행을 만든다.
2. 이름을 붙여 별도 저장한다. 보관은 자동 실행을 시작하지 않는다.
3. 저장 전략을 선택하고 **선택 전략 복제**를 누른다. 이름·이동평균 기간·최대 비중·주문 한도·진행 간격을 바꿔 새 전략으로 저장한다.
4. **같은 가격으로 새 실행**을 누르면 거래 기록을 새로 만들고 기존 스케줄러가 자동 진행한다. 원본 기록은 변경하지 않는다.
5. 비교할 실행을 선택한다. 진행 중에는 두 실행의 cursor 중 작은 값까지만 다시 계산하므로 서로 다른 날짜의 평가액을 직접 비교하지 않는다.

- V43의 `auto_trading_strategies`는 소유자, 이름, 원본 실행 ID, 불변 설정, 요청 키, 생성 시각을 보관한다. 실행의 nullable `strategy_id`로 연결하며 기존 실행도 유지된다.
- 원본 실행의 불변 `prices_json`을 복사하므로 이후 `price_history` 변경이나 삭제가 재실행에 영향을 주지 않는다. 원본 실행의 진행률과 관계없이 전체 고정 가격 사본을 사용한다.
- 전략은 최대 100개/계정, 기존 미완료 실행 한도는 5개/계정이다. 이름은 1~80자이며 같은 이름도 별도 ID로 구분한다. 기존 전략 수정·삭제 기능은 제공하지 않는다.
- 저장·재실행은 각각 사용자 행 잠금과 요청 키로 중복을 방지한다. 같은 키에 다른 설정·전략을 지정하면 거부한다.
- 복제 시 종목, 날짜 범위, 초기 자금, 수수료, 슬리피지, 알고리즘 버전은 원본과 같아야 한다. 프론트엔드뿐 아니라 서버에서도 검사한다.
- 실행 비교는 위 조건 및 전체 가격 사본의 일치를 검사한다. 불일치 시 `comparable=false`와 차이 필드를 반환하며 성과 표를 만들지 않는다.
- 비교는 두 SMA 전략 자체의 성과를 비교한다. 이동평균 준비 기간이 다른 것은 전략 차이이며 각각 해당 기간에 현금을 보유한 결과로 반영한다. 별도의 매수·보유 벤치마크는 이 표에 사용하지 않는다.
- 금융 계산은 기존 Python 비교 함수를 재사용하고 서버가 양쪽의 같은 날짜 범위를 결정한다. 비교 결과는 조회 시 계산하며 과거 상태·일지를 덮어쓰지 않는다.

## 성과 비교 v1

- Python의 `sma-comparison-v1` 계산을 조회 시 실행한다. 기존 실행 상태·매매 일지·전략 버전은 변경하지 않는다.
- 두 전략은 같은 초기 자금과 처리된 날짜 범위를 사용한다. SMA 준비 기간 N일은 모두 현금을 유지하고, 매수·보유는 N+1번째 거래일 시가에 한 번 매수한다. SMA가 실제로 첫 매수한 날과는 다를 수 있다.
- 매수·보유에도 동일한 최대 비중, 1회 주문 한도, 수수료, 슬리피지, 수량 정밀도를 적용한다. 따라서 100% 투자한 시장 지수 벤치마크는 아니며 남은 현금은 그대로 유지한다.
- 최종 강제 매도 없이 종가로 평가한다. 수익률, 최대 낙폭(초기 자금 포함 최고 평가액 기준), 체결 횟수, 누적 수수료, 초과 수익률(%p), 일별 평가 자산을 반환한다. 슬리피지는 체결 가격에 반영되며 수수료 합계에 포함하지 않는다.
- 실행 중에도 저장된 cursor까지만 비교한다. 미래 가격을 포함하지 않으며 일시정지·오류·종료 실행도 같은 방식으로 조회한다.
- 가격 품질은 `adjustment=UNKNOWN`, `dividends=UNKNOWN`, `missingSessions=NOT_CHECKED`로 명시한다. 날짜 정렬·중복·양수 가격 검증은 수행하지만 거래소 달력 기반 누락 검사는 하지 않는다. 배당 포함 총수익률로 해석할 수 없다.
- 기존 실행도 별도 마이그레이션 없이 비교 가능하다. 비교 결과는 고정 설정·가격으로 재계산하며 별도 DB 기록을 추가하지 않는다.

## 실행

```powershell
rtk docker compose -f compose.local.yml -f compose.execution.yml up -d --build
```

화면: http://localhost:13100/auto-trading

MySQL named volume이 기록의 원본이다. 중지하려면 `stop`을 사용하고 기록을 유지하려면 `down -v`를 사용하지 않는다.
