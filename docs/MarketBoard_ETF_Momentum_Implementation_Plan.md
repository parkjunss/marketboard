# ETF 상대 모멘텀 + 추세 필터 구현 방안

작성일: 2026-10-16

## General — 목적과 범위

투자자가 ETF 후보를 동일한 규칙으로 비교하고, 선정 근거를 확인한 뒤 투자 검토에 연결한다.
규칙은 검증 대상이며 최적 전략이나 수익 보장이 아니다. 1단계는 연구용 월말 스냅샷이다.
자동 주문, 매매 알림, 수익률 예측을 포함하지 않는다.

사용자 흐름: 스크리너 → ETF 순위/추세/데이터 상태 → 백테스트 비교 → 투자 검토 저장 → 모의 운용 → 리밸런싱 검토.
운영자 흐름: ETF 등록 및 일봉 수집 상태 확인 → 가격 조정 기준/휴장일 검증 → 누락 복구 → 전략 결과 공개.

**계산 책임 원칙:** 투자 계산은 서버에서 수행하고 프론트엔드는 조회·표시만 한다. Python에 규칙을 한 번 구현하며 Spring과 프론트엔드에서 중복 계산하지 않는다. [ADR 0002](adr/0002-server-owned-investment-calculations.md) 참조.

## Function — 단계별 구현

1. **ETF 순위와 추세 필터:** 기존 `/screener`에 연구용 패널 추가. Collector가 저장된 6개 ETF 일봉으로 모멘텀·200일선·편입 사유·현금 비중 계산. Spring 인증 API를 통해 결과 표시. 결측 시 제안 보류. 서버 순수 계산 모듈과 회귀 테스트 작성.
2. **백테스트 비교:** 기존 collector 백테스트 엔진에 전략 추가. SPY 보유, ETF 모멘텀 상위 3개, 모멘텀+추세 필터 비교. 다음 거래일 체결, 거래비용·슬리피지·현금 수익 가정, 동일 기간과 가격 조정 기준을 명시. 거래 기록·낙폭·회전율·시장 구간별 결과 제공.
3. **투자 검토 연결:** 기존 review 저장 흐름에 규칙 버전, 기준일, 입력 데이터 및 근거 스냅샷 연결. 사용자가 채택/보류하고 이유 기록.
4. **모의 운용:** 월별 신호를 불변 스냅샷으로 저장하고 이후 성과 추적. 과거 재계산 결과와 구분.
5. **리밸런싱 제안:** 기존 포트폴리오 보유/현금과 목표 비중 비교, 조정 금액 제시. 실제 주문은 별도 범위.

## Spec — 초기 전략 규칙

| 항목 | 규칙 |
|---|---|
| 고정 종목군 | SPY, QQQ, EFA, EEM, IEF, GLD |
| 판단 시점 | 뉴욕 날짜 기준 직전 완료 월말. 월중 실시간 순위가 아님 |
| 모멘텀 | `(직전 월말 종가 / 12개월 전 월말 종가 - 1) × 100`. 각 월말 당일 또는 그 이전 마지막 일봉 사용 |
| 예시 | 2026-09-30 판단: 2025-09-30 → 2026-08-31 가격 수익률. 최근 9월은 제외 |
| 순위 | 모멘텀 내림차순. 동률은 티커 알파벳순 |
| 선택 | 먼저 상위 3개 선정, 이후 각 ETF의 판단일 종가 > 최근 200개 일봉 종가 평균 검사 |
| 배분 | 통과 ETF당 정확히 1/3. 미통과 자리의 1/3은 현금. 4위 이하로 대체하지 않음 |
| 경계 | 종가 = 200일선이면 미통과. 별도 양의 모멘텀 조건은 추가하지 않음 |
| 주문 | 1단계 주문 없음. 후속 백테스트는 월말 신호 이후 다음 거래일 체결 |

## 1단계 구현 구조

- `collector/app/etf_momentum.py`: 고정 종목군, 서버 시각 기반 월말 산정, 일봉 DB 조회, 데이터 검사, 순위·비중 계산. 순수 계산 함수는 후속 백테스트에서도 재사용한다.
- `collector/tests/test_etf_momentum.py`: 날짜 경계·최근 월 제외·현금·동률·결측 및 DB 조회 경계 검증.
- `collector/main.py`: 내부 `GET /strategies/etf-momentum`. DB/계산 장애는 502이며 결측 신호로 대체하지 않는다.
- Spring `EtfMomentumController`, `CollectorClient`, `EtfMomentumResult`: 인증된 `GET /api/screener/etf-momentum`, 응답 DTO 및 Collector 연결. 엔진 장애는 503.
- `frontend/src/lib/etf-momentum-types.ts`, `api.ts`: 서버 응답 타입과 조회 함수. 프론트엔드 계산 모듈·계산 테스트는 제거했다.
- `frontend/src/components/screener/EtfMomentumPanel.tsx`: API 결과 표시, 재조회 버튼, 로딩/오류/제안 보류 표시. 비중을 더하거나 순위를 재정렬하지 않는다.
- `frontend/src/app/(app)/screener/page.tsx`: 기존 화면에 패널 연결.
- DB 스키마·의존성 변경 없음. 조회는 종목 ID 인덱스와 UTC 기간 조건으로 약 1년의 저장된 일봉만 읽으며 외부 가격 수집/DB 쓰기를 수행하지 않는다.
- 기존 `api.ts`의 사용자 타임아웃 변경은 보존하고 조회 함수를 추가한다. Docker/Compose 및 뉴스 CSS는 수정하지 않는다.

### 데이터 검증 및 한계

6개 ETF 모두 유효한 이력과 동일한 계산 구간 거래일 집합을 가져야 순위와 비중을 제시한다.
미등록/빈 이력/부족한 이력/중복 일자/비정상 종가/날짜 불일치 시 전체 제안 보류. DB/계산 서버 장애는 별도 조회 오류로 표시한다.
개별 ETF에서 계산 가능한 지표는 보류 사유와 함께 표시한다.
월말 기준 가격과 모멘텀 양 끝점은 목표일 이전 7일 이내여야 하며, 계산 구간 내 7일 초과 공백은 거부한다.
가격을 보간하거나 결측 종목을 제외한 작은 종목군으로 순위를 내지 않는다.

현재 백필 코드는 yfinance `auto_adjust=True`를 사용하지만, 기존 일봉 API에는 공급자/조정 방식 메타데이터가 없다.
따라서 저장된 모든 가격의 조정 일관성을 보장하거나 배당 포함 총수익률이라고 표시하지 않는다.
거래소 캘린더는 아직 적용하지 않았으므로 모든 ETF에 동시에 빠진 일부 거래일은 감지하지 못할 수 있다.
추후 실거래/신호 배포 전 공식 거래일 대조, 조정 이력, 데이터 출처·최신성 검증이 필요하다.
SPY·QQQ 중복 노출, 횡보장 손실, 반등 재진입 지연은 전략 자체의 위험이다.

## 2단계 구현 — ETF 백테스트 비교

- `/screener`의 **전략 백테스트 비교** 링크로 `/backtest#etf-comparison`에 접근한다.
- 인증된 `POST /api/backtest/etf-comparison` → Collector `POST /backtest/etf-comparison`.
- 입력: `startDate`, `endDate`, `initialCapital`(USD, 1~10억), `feeBps`, `slippageBps`(각각 편도 0~100bp). 시작일 < 종료일, 최대 3660일, 1991년 이후, 종료일은 뉴욕 기준 오늘 이전이다.
- `collector/app/etf_backtest.py`가 세 전략을 같은 일봉·기간·자본·비용으로 계산한다. 신호는 1단계의 `build_etf_momentum`, 성과 지표는 기존 백테스트에서 추출한 공통 `performance_metrics`를 사용한다.
- `load_daily_bars`는 최초 신호 월말의 12개월 전 월말보다 7일 앞부터 종료일까지 저장된 시가·종가를 읽는다. 원래 일봉 조회 기능은 같은 로더에서 종가만 선택한다.
- 결과 저장·투자 검토 연결은 3단계다. 이 비교 API는 DB에 쓰지 않으므로 생성용 idempotency 키를 요구하지 않는다.

### 체결·비용·성과 규칙

1. 매월 첫 관측 거래일에 직전 월말 신호를 적용한다. 시작일이 월중이면 첫 관측 거래일에 직전 월말 신호로 초기 편입한다. 신호와 같은 날의 종가로 소급 체결하지 않는다.
2. SPY는 첫 거래일 시가에 매수하고 보유한다. 모멘텀은 상위 3개 동일 비중, 추세 필터 전략은 같은 상위 3개에 200일선 필터를 추가한다. 월마다 목표 비중으로 재조정한다.
3. 소수점 수량을 허용한다. 기존 보유 수량은 교체일 시가로 평가하므로 야간 가격 변화도 반영한다. 비용 차감 후 자산 기준으로 목표 비중을 맞추며 현금을 빌려 비용을 지불하지 않는다.
4. 수수료와 슬리피지는 시가 기준 매수·매도 거래대금에 각각 적용한다. 슬리피지는 별도의 체결 가격 이동 대신 현금 비용으로 모델링한다. 현금 이자와 샤프 무위험 금리는 0%, 세금 없음, 종료일 강제 매도 없음.
5. 초기 현금 기준으로 누적 수익률·낙폭을 계산하여 첫 매수 비용과 첫날 시가→종가 수익을 포함한다. CAGR은 첫 관측 거래일 전날부터 종료일까지의 경과일/365.25, 변동성·샤프는 252거래일 연율화다.
6. 회전율은 각 교체의 `(매수대금+매도대금)/거래 전 시가 평가 자산`의 기간 누적 합계다. 연율화하거나 2로 나누지 않으며 최초 편입도 포함한다.
7. 시장 구간은 전 거래일까지 SPY 63거래일 수익률이 +5% 초과이면 상승, -5% 미만이면 하락, 나머지는 횡보다. 구간별 일간 수익률을 복리로 연결하며 불연속 날짜 묶음임을 표시한다. 사후 구간 분류로 종목을 고르지 않는다.

### 응답과 장애 구분

- 정상: `ready=true`, 요청/실제 관측 기간, 비용 조건, USD 통화, 전략별 성과·일별 자산/누적 수익률·거래 기록·월별 목표 비중·시장 구간별 성과.
- 6개 ETF 중 하나라도 누락, 중복, 비정상 가격, 거래일 불일치, 충분한 준비 이력 부재, 7일 초과 공백 또는 요청 시작/종료 근처 가격 부재이면 **전체 비교 보류**. 200/`ready=false`/`message`/빈 전략 목록으로 응답한다. 교집합 거래일로 줄이거나 준비 기간 뒤부터 몰래 시작하지 않는다.
- 입력 검증 실패: Spring 400. 미인증: 401. Collector 장애: Spring 503. 오류와 데이터 부족을 0% 수익률로 바꾸지 않는다.
- Collector 호출은 30초, 프론트엔드 비교 요청만 40초 제한이다. 기존 공통 10초 타임아웃은 유지한다.
- Frontend는 서버가 제공한 `returnPct`, 지표, 거래, 목표 비중을 포맷해 표시한다. 성과 계산·순위·임계값 판단을 추가하지 않는다.

현재 저장된 가격의 조정 기준과 공식 휴장일 캘린더 대조는 여전히 미검증이다. 모든 종목에 동시에 빠진 짧은 공백은 감지하지 못할 수 있으므로 결과는 연구용이다. 실제 운용 전 조정 데이터/캘린더 검증과 구간 외 검증이 필요하다.

## 3~5단계 구현 (2026-10-16)

### 검토 저장과 판단

- `/etf`에서 기간·자본·비용·전략을 입력하면 서버가 다시 계산하여 기존 `investment_reviews`에 저장한다. 비교 화면에서 이전에 본 결과와 동일하다고 가정하지 않는다.
- 기존 Payload의 선택 필드 `etf`에 규칙 버전, 선택 전략, 비교 결과와 계산에 사용한 전체 일봉을 함께 동결한다. 기존 기록은 해당 필드가 없어도 복원한다.
- `POST /api/etf/reviews`는 기존 V25 멱등 키를 사용한다. 재시도는 최초 저장 응답을 재생하며 계산 서버를 다시 호출하지 않는다.
- `GET /api/etf/reviews`는 최근 전체 검토 50건 중 ETF 기록의 요약만 반환한다. 상세와 채택/보류/추가 확인 판단은 기존 소유자 전용 review API를 재사용한다.

### 모의 운용

- 가장 최근 판단이 `EXECUTE`인 ETF 검토에서만 시작한다. 자본·비용·전략·계산 버전은 변경 불가 검토 기록을 참조한다.
- V38은 별도 `etf_paper_accounts`와 `etf_paper_snapshots`를 추가한다. 계좌 상태만 갱신하고 월별 신호와 일별 평가·체결·입력 가격은 append-only로 보존한다.
- 신호를 실제 저장한 뉴욕 날짜보다 **뒤의** 첫 관측 거래일 시가에 체결한다. 장 시작 전 저장했더라도 같은 날 체결하지 않는 보수적 규칙이다. 시작 시 과거 백테스트 거래를 생성하지 않는다.
- 신호가 없으면 현금을 유지한다. 새 월말 신호를 놓치면 이전 보유를 유지하며 과거 월별 신호를 소급 생성하지 않는다. 수집 재개 후 저장한 신호도 저장일 이후에만 적용한다.
- 매일 08:30 UTC 스케줄 및 수동 갱신을 지원한다. 계좌 행 잠금과 `(계좌, 종류, 기준일)` 유일 제약으로 동시/반복 갱신의 중복 기록을 방지한다. 시작은 V25 멱등 키를 사용한다.
- 6종목 거래일 불일치, 7일 초과 이력 공백, 비정상 가격이면 평가를 보류한다. 계산 서버 장애 시 이전 상태와 이미 저장한 신호를 유지한다. 중지는 기록을 보존하고 후속 계산만 막는다.
- 운영 서버의 V38 적용 및 정상 수집/스케줄러 실행이 필요하다. 이번 작업은 운영 DB에 마이그레이션을 실행하지 않는다.

### 리밸런싱 제안

- `POST /api/etf/rebalance`는 소유 검토·포트폴리오를 확인한 뒤 서버에서 보유 수량/버전과 비중 제한을 읽는다. 프론트에서 계산하거나 전달한 보유 수량을 신뢰하지 않는다.
- 기존 포트폴리오 원장에는 현금 잔액이 없으므로 사용자가 확인한 **USD 가용 현금**을 입력한다. 추정한 잔액을 실제 현금으로 제시하지 않는다.
- 현재 월말 신호와 모든 보유 종목/ETF의 공통 최신 완료 일봉 종가로 조정 수량·금액·예상 현금·비용을 계산한다. 가격일이 다르거나 4일보다 오래되면 보류한다.
- 전략 목표가 포트폴리오 최대 비중 규칙을 초과하면 임의로 비중을 바꾸지 않고 보류한다. ETF 집합 밖의 기존 종목은 목표 0으로 제안한다.
- 결과는 표시만 하며 주문, 실제 포지션, 거래 원장에 쓰지 않는다. 표시된 버전·가격일 이후 보유나 시세가 바뀌면 재계산이 필요하다.

### 운영 및 검증 경계

- 계산은 Collector/Python, 인증·소유권·멱등 저장은 Spring, 프론트는 입력/표시를 맡는다. 별도 계산 의존성을 추가하지 않았다.
- 조정 가격의 배당/분할 반영 여부, 공식 거래소 휴장일, 세금·환전·실제 체결은 여전히 검증 범위 밖이다. 연구용 표시를 유지한다.
- 신규 Python 금융 계산 테스트와 Spring 인증/검증·격리 H2 저장 테스트를 추가했다. 실제 MySQL 적용과 로그인 브라우저의 전체 서비스 연동은 별도 검증이 필요하다.
