# MarketBoard 통합 개선 계획

- 최초 작성: 2026-10-21
- 개정일: 2026-10-22
- 대상: https://marketboard.duckdns.org
- 근거: 이전 비로그인 데스크톱 화면 검토 및 사용자 추가 제안
- 목표: 시장 파악 → 종목 탐색 → 상세 확인 → 개인화 기능 활용으로 이어지는 흐름 구성

## 1. 전체 방향

MarketBoard에는 지수, 시장 폭, 투자 심리, 섹터, 종목, 뉴스 등 유용한 재료가 있다. 다만 페이지 역할과 정보의 우선순위가 약하고, 정보를 확인한 뒤 다음 행동으로 이어지는 연결이 부족하다.

이번 개선은 기존 기능을 정리하고 로딩·공유·로그인·데이터 신뢰 표시를 보완하는 데 집중한다. 신규 데이터 수집, AI 요약, 번역은 별도 범위로 결정한다.

이번 문서 개정에서는 사이트를 다시 점검하지 않았다. 이전 관찰과 추가 제안을 아래처럼 구분한다.

## 4. 로딩과 오류 경험

### 4.1 스켈레톤 UI

- 텍스트만 표시하는 로딩 영역을 차트·카드·표 형태의 스켈레톤으로 개선한다.
- 실제 콘텐츠의 예상 크기를 확보해 로딩 완료 후 화면이 크게 밀리지 않게 한다.
- 지수·차트·뉴스를 가능한 범위에서 독립적으로 표시한다. 일부 API 지연이 전체 화면을 막지 않게 한다.
- 이전 데이터가 있다면 기준 시점과 갱신 중 상태를 함께 표시하며 유지하는 방식을 검토한다.
- 과도한 점멸을 피하고 동작 줄이기 설정을 고려한다.

### 4.2 상태별 처리

| 상태 | 화면 안내 | 다음 행동 |
| --- | --- | --- |
| 최초 로딩 | 영역별 스켈레톤, 로딩 상태 | 다른 영역 이용 가능 |
| 긴 지연 | 시간이 걸린다는 안내 | 요청 종료 후 재시도 가능 |
| 요청 실패 | 실패 영역과 간결한 오류 안내 | 해당 영역 다시 불러오기 |
| 빈 결과 | 검색 결과 없음 등 원인에 맞는 안내 | 검색어·조건 수정 |
| 연결 끊김 | 마지막 수신 시점, 연결 상태 | 재연결 상태 확인 |
| 이전 데이터 | 기준 시점과 갱신 지연 표시 | 지연 데이터 참고 또는 재시도 |

타임아웃과 자동 재시도 정책은 실제 응답 시간·API 제한을 확인해 정한다. 자동 재시도는 횟수·간격을 제한하고 실패 시 안내로 종료한다. 중복 요청을 막고 실패한 영역만 재시도한다.

완료 검증: 느린 응답, 네트워크 단절, API 오류, 빈 응답을 각각 재현해 끝없는 대기 화면이 남지 않는지 확인한다.

## 5. 정보 구성

### 5.1 대시보드: 오늘의 핵심 변화

| 순서 | 영역 | 내용 |
| --- | --- | --- |
| 1 | 핵심 지표 | 주요 지수, 환율·VIX 중 서비스 대상에 맞는 소수 항목 |
| 2 | 시장 요약 | 상승·하락 비중, 투자 심리, 특징적 변화 |
| 3 | 대표 차트 | 선택 지수 차트와 기준 시점 |
| 4 | 주목할 종목·섹터 | 소수 항목과 상세 이동 |
| 5 | 뉴스·개인화 안내 | 소수 뉴스와 관련 기능 진입 |

- 기존 지표를 선별하고 긴 표·설명은 시장 동향으로 이동한다.
- KOSPI 등 국내 지수는 대상 이용자와 데이터 범위를 확인한 뒤 추가 여부를 결정한다.
- 차트 높이와 인접 카드 폭을 조정해 빈 공간과 과도한 줄바꿈을 줄인다.
- 요약 문구는 수치로 설명 가능한 표현부터 적용한다. AI 기능 추가를 전제로 두지 않는다.

### 5.2 시장 동향: 세부 비교

- 시장 폭, 투자 심리, 섹터, 거시 지표로 영역을 묶는다.
- 대시보드의 전체 카드를 반복하기보다 비교 기간·추이·정의 등 추가 정보를 제공한다.
- 중복 섹션 제목을 정리한다.
- 과거 추이와 기준일 비교는 데이터가 지원할 때 제공한다.

### 5.3 섹터 로테이션

기존 1일·1주·1개월 표를 기반으로 기간 선택과 정렬을 개선한다. 사용자 제안의 3개월은 확장 검토 항목이다.

- 1주·1개월·3개월 등의 선택 기간에 맞춰 정렬·시각화가 함께 바뀌게 한다.
- 3개월 데이터의 수집·산출 가능 여부를 먼저 확인한다. 없는 값을 임의로 채우지 않는다.
- 막대 차트 또는 히트맵 중 비교 목적에 맞는 하나를 우선 적용하고 수치 표도 유지한다.
- 기간·부호·수치를 제공해 색상만으로 해석하지 않게 한다.
- 섹터 ETF 수익률과 벤치마크 대비 상대강도를 구분해 계산식에 맞는 용어를 사용한다.
- 섹터별 종목 이동은 분류 데이터가 지원하는 범위에서 제공한다.

### 5.4 데이터 시점과 출처

- 주요 지표·차트에 기준 일시, 시간대, 출처를 표시한다.
- ‘5분 전 업데이트’ 같은 상대 시간과 정확한 기준 시각을 함께 확인할 수 있게 한다.
- 데이터 기준 시각, 서버 수집 시각, 화면 갱신 시각을 혼동하지 않는다.
- 실시간·지연·장 마감·일봉·이전 데이터 상태를 구분한다.
- 서로 다른 시점의 자료에 하나의 시각을 붙여 모두 동시 데이터처럼 보이게 하지 않는다.
- ‘실시간’ 표현은 실제 제공 범위와 지연 조건을 확인한 뒤 사용한다.

## 6. 종목 검색과 뉴스

### 종목 검색

- 기본 열은 종목, 가격, 등락률, 거래량, 대표 추이 중심으로 줄인다.
- 연간 고가·저가는 추가 열 또는 상세로 제공한다.
- 정렬 기준과 검색 범위를 표시한다.
- 전역 검색은 종목 바로 이동, 목록 검색은 현재 목록 필터처럼 역할을 구분한다.
- 가격 기준 시점과 실시간 연결 상태를 따로 표시한다.
- 추가 로딩·실패·빈 결과 안내를 구분한다.

### 뉴스

- 제목, 작은 출처, 발행 시각을 우선 배치한다.
- 제목과 같은 설명은 생략하고 추가 정보가 있을 때만 표시한다.
- 반복되는 큰 언론사 로고를 작은 출처 표시로 줄인다.
- 신뢰할 수 있는 연결 정보가 있을 때 종목·섹터 태그를 제공한다.
- 영문 원문 제공 여부를 명확히 한다. 번역은 별도 기능으로 판단한다.

## 7. 개인화 미리보기와 로그인 전환

- 실제 이용 가능한 관심종목 등 기능을 짧은 미리보기로 설명한다.
- ‘로그인하고 관심종목 관리하기’처럼 행동과 가치를 연결한 CTA를 제공한다.
- 예시 데이터는 예시임을 표시하고 실제 사용자 데이터처럼 보이게 하지 않는다.
- 핵심 정보를 가리는 가입 배너를 남발하지 않는다.
- 관심종목 등 기능의 실제 구현 여부와 동작은 로그인 이후 별도로 확인한다.

로그인 흐름:

1. 제한 기능 진입 전에 로그인 필요 여부를 안내한다.
2. 선택 종목과 원래 화면을 보존한다.
3. 로그인 화면에서도 사용 목적을 유지한다.
4. 로그인 성공 후 원래 화면으로 복귀한다.
5. 관심종목 추가 등 미완료 행동의 상태를 복원하고 완료 여부를 알린다.

복귀 경로는 허용된 내부 경로로 제한하고 URL에 개인정보·인증 정보를 넣지 않는다. 공개 상세 일부 제공 여부는 데이터 제공 조건과 인증 정책을 확인한 뒤 결정한다.

## 8. SEO와 공유

### 8.1 페이지 메타데이터

description 불일치 제안은 경로별 실제 응답을 확인해 반영한다. 같은 메타데이터를 모든 페이지에 일괄 적용하지 않는다.

| 페이지 | title 예시 | description 방향 |
| --- | --- | --- |
| 대시보드 | 시장 대시보드 · MarketBoard | 지수와 투자 심리, 주요 변화 요약 |
| 시장 동향 | 시장 동향 · MarketBoard | 시장 폭, 섹터, 거시 지표 비교 |
| 종목 검색 | 종목 검색 · MarketBoard | 종목별 가격·거래량·추이 비교 |
| 뉴스 | 시장 뉴스 · MarketBoard | 시장 뉴스 제목·출처·발행 시각 확인 |

- 경로별 title, description, canonical, OG title·description·image를 점검한다.
- 실제 공유 서비스에서 제목·설명·이미지가 정상 표시되는지 확인한다.
- OG 이미지에 실시간 가격을 넣으려면 갱신 정책이 필요하다. 기본 이미지는 서비스·페이지 정체성을 표현하는 방식이 적합하다.

### 8.2 초기 HTML과 SSR/ISR 검토

- JavaScript 실행 전 HTML에 제목·설명·메타데이터·공개 핵심 정보가 있는지 확인한다.
- 초기 HTML에 데이터가 없다는 이유만으로 모든 검색 엔진에서 빈 페이지로 보인다고 단정하지 않는다.
- OG 태그 제공과 본문 수치 사전 렌더링을 별도 작업으로 다룬다.
- 필요 시 공개 요약 영역에 SSR/ISR 등 사전 렌더링을 검토한다. 차트의 실시간 갱신과는 분리할 수 있다.
- Next.js라면 현재 버전·라우터·인증 구조를 확인한 뒤 서버 컴포넌트와 재검증 정책의 적용 범위를 정한다. 특정 API나 설정을 이 문서에서 확정하지 않는다.
- 공유 캐시에는 공개 데이터만 포함하고 개인화·인증 데이터가 섞이지 않게 한다.
- 캐시 주기는 데이터 갱신 주기·서버 부하에 맞추고 캐시된 수치의 기준 시점을 표시한다.

완료 검증: 공개 경로의 HTML 응답과 실제 공유 결과를 각각 확인한다. 다른 페이지의 메타데이터나 로그인 화면이 의도치 않게 공유되지 않아야 한다.

## 9. 신뢰 표시와 정보 이용 고지

- 푸터에 정보 제공 목적, 투자 판단 책임, 지연·오류 가능성을 간결하게 안내한다.
- 데이터 출처와 이용 조건에서 요구하는 표시를 별도로 확인한다.
- 기준 시점·지연 안내는 해당 지표 근처에도 표시한다.
- 고지를 데이터 정확성 관리나 장애 안내의 대체물로 사용하지 않는다.

문구 초안:

> MarketBoard의 정보는 참고용이며 투자 권유를 목적으로 하지 않습니다. 데이터는 출처와 제공 조건에 따라 지연되거나 오류가 있을 수 있습니다. 투자 판단과 그에 따른 책임은 이용자 본인에게 있습니다.

이 문구는 제품 문구 제안이다. 특정 법적 의무 충족이나 책임 면제를 보장하지 않으며 실제 서비스 범위와 데이터 이용 조건에 맞게 검토한다.

## 10. 테마·접근성·모바일

### 테마 확인 순서

1. 웹페이지 강제 다크모드와 색상 변경 확장 기능을 끄고 확인한다.
2. 기본 밝은 모드와 어두운 모드에서 확인한다.
3. 사이트 테마 기능이 있다면 브라우저 설정과 분리해 확인한다.
4. 차트 배경·축·격자·캔들, 카드·표·입력창의 결과를 기록한다.
5. 강제 다크모드 결과와 비교해 원인을 좁힌다.

이전 검토에서 보인 검은 글자는 원인 확인 전 사이트 결함으로 확정하지 않는다.

### 접근성

- 기존 일부 화면에는 등락 부호·방향 표시가 이미 있었다. 없는 영역까지 일관되게 제공하는지 확인한다.
- 차트의 핵심 수치는 텍스트로도 제공한다.
- 키보드로 검색·버튼·기간 선택을 조작하고 초점을 식별할 수 있는지 확인한다.
- 텍스트 대비, 입력 레이블, 로딩·오류 상태 안내를 점검한다.
- 과도한 줄바꿈을 줄이고 단위·날짜·숫자 정렬을 통일한다.

### 모바일

- 카드가 좁아져 단어·숫자가 한 글자씩 끊기지 않게 한다.
- 표는 핵심 열 우선 표시 또는 표 내부 가로 스크롤을 사용한다.
- 가로 스크롤 자체보다 페이지 전체가 밀리거나 핵심 정보에 접근할 수 없는지를 확인한다.
- 차트 축·툴팁·기간 버튼과 메뉴가 작은 화면에서 동작하는지 확인한다.
- 확대 시 겹침·잘림을 확인한다.
- 작은 모바일, 큰 모바일, 데스크톱 폭에서 주요 이용 흐름을 점검한다.
