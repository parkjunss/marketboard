## General — 목적과 범위

사용자가 여러 화면을 오가며 해석하던 자료를 읽을 수 있는 보고서로 묶는다. 전체 시장의 변화에서 관심 종목 확인으로 이어지고, 매일 방문하지 않아도 선택한 보고서를 이메일로 받아 다시 웹에서 근거를 확인할 수 있게 한다.

핵심 원칙은 **보고서를 먼저 생성·저장하고 웹과 메일이 같은 버전을 참조하는 것**이다. 메일 발송 시점에 수치와 뉴스를 새로 조회해 과거 보고서의 의미를 바꾸지 않는다. 수익률·위험·순위 계산은 백엔드/collector가 담당하고 프런트엔드는 결과를 표시한다.

초기 범위는 미국 주식시장 중심의 일일 마감 보고서다. 화면의 ‘오늘’은 발행일을 의미하며 제목에 실제 대상 거래일을 함께 표시한다. 예: `10월 23일 시황 브리핑 — 미국장 10월 22일 마감 기준`. 다른 국가·장중 속보·주간/월간·PDF 첨부·AI 생성 평론은 후속 확장으로 둔다.

### 현재 코드에서 확인한 기반

| 기반 | 확인한 내용 | 필요한 확장 |
| --- | --- | --- |
| `report/ReportService.java` | 가격·일봉 252개·재무·정량 분석을 수집하고 일부 실패와 시점 주의사항을 payload에 저장. schema/calculation version 존재 | 일일 시장 보고서, 읽기 쉬운 요약 구조, 자료별 출처/거래일 보강 |
| `report/ReportController.java` | `/api/reports` 종목 보고서 생성·종목별 목록·ID 조회, 계정 소유권과 멱등성 흐름 | 기존 계약 호환 유지, 시장 보고서와 권한 분리 |
| `mail/DailyReportMailer.java` | 기본 08:00 Asia/Seoul 스케줄, 활성 구독자, 뉴스 제목 최대 10개, 실패 로그 | 보고서 참조, 영속 발송 이력/대기열, 재시도·중복 방지·반송 처리 |
| `mail/MailService.java` | JavaMailSender로 단순 텍스트 메일 전송 | HTML+텍스트 대체 본문, 발송 결과와 제공자 상태 연동 |

이 표는 소스 확인 결과다. SMTP 설정, 운영 발송 스케줄, 전달률, 기존 수신 동의 범위는 별도 확인이 필요하다. 기존 스케줄러가 발송 전에 인앱 알림을 만드는 점도 ‘보고서 발행’과 ‘메일 전달 성공’을 혼동하지 않게 정리한다.

## Function — 사용자 흐름과 역할

### 1. 시황 보고서 읽기

대시보드의 ‘오늘의 시황 보고서’ → 발행일/대상 거래일/완성 상태 확인 → 핵심 요약 → 지수·섹터·뉴스 근거 → 관련 종목 상세/보고서로 이동한다. 날짜별 과거 보고서 목록을 제공하고 오늘 보고서가 없으면 마지막 발행일과 생성 상태를 보여 준다.

공개 시황 보고서의 비로그인 열람을 기본안으로 하되 공급 데이터의 재배포 조건을 확인한다. 비공개 개인 보고서와 같은 캐시·조회 권한을 사용하지 않는다. 이메일 구독은 로그인 사용자에게 제공한다.

### 2. 종목 보고서 만들고 읽기

종목 상세의 기존 보고서 기능 → 생성 요청 → 진행/실패/부분 완료 안내 → 저장 보고서 확인 → 이전 보고서 선택으로 이어진다. 새로고침·중복 클릭에도 같은 생성 요청을 중복 실행하지 않는다. 로그인 전 진입은 선택 종목으로 복귀하며, 유료 계산이나 보고서 생성 같은 쓰기 작업을 로그인만으로 자동 실행하지 않는다.

기존 개인 보고서는 소유자만 조회한다. 여러 사용자가 같은 종목을 구독하면 원천 분석 결과를 재사용할 수 있지만, 기존 개인 보고서를 그대로 공유하거나 권한 검사를 생략하지 않는다.

### 3. 이메일 구독·해지

프로필/보고서 화면 → 인증된 수신 주소 확인 → `전체 시황`, `선택 종목`을 각각 선택 → 종목 목록과 발송 시간 확인 → 동의 저장 → 다음 예정 발송 표시로 이어진다. 초기 종목 제한은 계정당 최대 5개를 제안하며 비용·부하 검증 후 확정한다.

기본 발송은 기존 08:00 Asia/Seoul을 유지하는 안으로 시작한다. 시간대·개인별 시간 선택은 후속 확장으로 둔다. 선택 종목은 명시적으로 저장하며 관심종목 전체를 자동 구독하지 않는다. 관심종목 변경만으로 발송 대상이 예고 없이 바뀌면 안 된다.

메일에는 수신 이유, 해당 구독 해지 링크, 설정 링크, 보고서 링크를 포함한다. 로그인 없이 제한된 토큰으로 해당 구독을 해지할 수 있게 한다. 일반 링크의 GET 방문은 메일 보안 스캐너에 의해 실행될 수 있으므로 확인 화면을 제공하고, 표준 one-click 해지는 별도 POST 흐름으로 설계한다. 해지·동의 철회 후 대기 중인 작업도 발송 직전에 다시 검사한다.

### 4. 운영자 흐름

대상 거래일별 생성 상태, 실패 원인, 자료 수신 지연, 발송 대기/성공/실패/반송 수를 조회한다. 재생성과 재발송은 구분하고 중복 방지 키를 유지한다. 테스트 발송은 검증된 테스트 수신자만 대상으로 하며 비밀키·메일 본문·개인정보를 로그에 남기지 않는다.

## Spec — 보고서 내용과 데이터 요구사항

### A13 전체 시황 보고서

| 구역 | 초기 내용 | 자료 부족 시 |
| --- | --- | --- |
| 헤더 | 발행일, 대상 시장/거래일, 생성 시각, 버전, 완료/부분 완료 | 지연·휴장·미발행 명시 |
| 핵심 요약 | 지수 방향, 상승/하락 비중, 강세/약세 섹터 등 근거 있는 3~5개 항목 | 확인한 수치만 서술 |
| 주요 지수 | 종가, 전 거래일 대비 등락, 기간 수익률 | 없는 지표는 미제공 |
| 시장 폭·심리 | 상승/하락/보합, 신고가/신저가, 공포·탐욕, Put/Call | 기준일이 다르면 구분 표시 |
| 섹터 | 1일·1주·1개월 수익률, 상하위 섹터 | 종목/섹터별 누락 표시 |
| 거시 지표 | VIX·달러·미국 금리·금·유가 | 관측 시각과 단위 명시 |
| 주요 뉴스 | 중복 정리된 제목, 출처, 발행 시각, 원문 링크 | 뉴스 없음과 조회 실패 구분 |
| 확인 사항 | 자료 지연·누락·가격 조정 여부·참고용 고지 | 보고서 자체를 최신이라고 단정하지 않음 |

뉴스와 주가가 같은 날 움직였다는 이유로 인과관계를 단정하지 않는다. 향후 일정은 별도 검증된 일정 데이터가 생길 때 추가하며 뉴스에서 추측해 채우지 않는다.

### A14 개별 주식 보고서

기존 payload와 과거 보고서를 읽을 수 있게 유지하면서 가격·거래량·기간 수익률, 추세/기술 지표, 재무 현황, 위험 분석, 관련 뉴스, 확인할 사항 순서로 제공한다. 재무 공시 기간·공시일·수집일은 구분하고 확보하지 못한 메타데이터는 미제공으로 둔다. 수집 시각을 실적 발표일로 대신하지 않는다.

각 요약 문장은 근거 지표 또는 원문으로 연결한다. 재무·분석을 구하지 못해도 확보된 자료로 부분 보고서를 만들 수 있으나 필수 가격/거래일 자료까지 없으면 발행을 보류한다. 매수·매도 추천이나 목표가를 자동으로 만들어 넣지 않는다.

기존 생성 API의 동기 비용과 타임아웃을 측정한다. 오래 걸리는 생성은 영속 작업으로 전환하고 `QUEUED → RUNNING → READY / PARTIAL / FAILED` 상태와 재조회 API를 제공한다. 기존 호출자는 즉시 완료 응답을 기대할 수 있으므로 별도 버전/신규 생성 경로 등 호환 방식을 먼저 결정한다.

### 거래일·시점·재현성

- 미국 거래소 달력과 `America/New_York` 시간대를 사용해 DST·휴장·조기 폐장을 처리한다. 한국 날짜에서 하루를 빼는 방식으로 거래일을 추측하지 않는다.
- 초기 정기 발행은 직전 완료 거래일의 마감 데이터 수집 완료 후 실행한다. 새 거래일이 없으면 같은 보고서를 새 보고서처럼 다시 발송하지 않는다. 휴장 안내 메일은 별도 옵션으로 남긴다.
- 정해진 발송 시각까지 필수 데이터가 준비되지 않으면 지연 상태로 둔다. 당일 재시도 마감 시각과 부분 발행 허용 기준은 운영 정책으로 확정한다.
- 보고서에 자료별 `asOf`, `fetchedAt`, 출처, 시장/통화, 계산 버전, 스키마 버전, 누락/품질 상태를 저장한다. 생성 시각은 원본 시각을 대체하지 않는다.
- 발행본은 불변 스냅샷이다. 정정은 새 버전과 사유를 기록하고 기존 발송 링크가 가리키는 내용은 유지한다. 정정 알림 발송 여부는 별도 정책으로 둔다.
- 동일 시장·거래일·보고서 종류·버전의 생성은 멱등 처리한다. 종목 보고서는 ticker와 소유권/공유 범위까지 키에 포함한다.

### A15 발송 구조

| 대상 | 저장/처리 요구사항 |
| --- | --- |
| 보고서 | ID, 종류, 소유/공개 범위, 거래일, 버전, 상태, payload, 생성 실패 정보 |
| 구독 | 사용자, 인증된 주소, 유형, 선택 종목, 동의/철회 시각, 상태, 정책 버전 |
| 발송 작업 | 구독 ID, 보고서 ID/버전, 예약 시각, 상태, 시도 횟수, 다음 재시도, 제공자 메시지 ID |
| 결과 이벤트 | 접수/전달/반송/신고/억제 등 제공자가 실제 확인해 준 상태, 이벤트 중복 방지 |

초기 저장소와 스케줄러는 기존 Spring/MySQL 구조를 우선 활용한다. 보고서 발행 트랜잭션과 발송 대기열을 outbox 방식으로 연결하고, 다중 인스턴스에서도 하나의 작업만 선점하도록 한다. 긴 외부 호출 동안 DB 트랜잭션을 열어두지 않는다.

`수신자+구독 종류+보고서 ID/버전`의 발송 중복을 막고, 시간 초과 후 전달 여부를 모르는 경우를 별도로 관리한다. SMTP만으로 정확히 한 번 전달을 보장할 수 없으므로 제공자 멱등키/상태 조회 지원을 확인한다. 일시 오류는 횟수 제한·지수 지연으로 재시도하고 영구 반송·신고 주소는 발송 억제한다. SMTP/API 접수 성공을 받은 편지함 도착으로 표현하지 않는다.

메일은 핵심 요약과 링크 중심 HTML 및 plain-text 대체 본문으로 구성한다. 외부 제목·본문은 escape하고, 이미지 없이도 읽을 수 있게 한다. 개인 보고서 링크는 로그인/소유권 검증을 거치며 영구 토큰으로 비공개 보고서를 공개하지 않는다. 웹 공개 범위와 원문 재배포 조건은 메일에도 동일하게 적용한다.

운영 도입 전 발신 도메인 SPF/DKIM/DMARC, 반송/신고 webhook 인증과 중복 이벤트 처리, 발송량 제한, 비용, 주소 보관/삭제 정책을 확인한다. 기존 `dailyReportEnabled` 사용자를 새로운 종목 구독이나 확대된 발송 빈도로 자동 전환하지 않는다. 기존 스케줄러와 신규 작업을 함께 켜 이중 발송하지 않도록 전환/롤백 순서를 정한다.

### 화면·API 초안

- 화면: 보고서 목록 허브, 날짜별 시황 상세, 기존 종목 보고서 목록/상세 확장, 프로필의 구독 설정, 운영자의 생성·발송 현황.
- API: 기존 `/api/reports` 개인 보고서 계약 유지. 시장 보고서 목록/상세, 생성 작업 조회, 본인 구독 조회·수정, 해지 토큰 처리, 운영자 재시도 경로를 추가하는 안을 검토한다. 정확한 URI는 구현 설계에서 확정한다.
- 신규 테이블/필드에는 Flyway migration, 사용자 소유권·공개 범위 테스트, 생성/발송 멱등성 제약, 조회 인덱스와 보존 정책을 함께 포함한다.

## 실행 순서와 완료 기준

| 단계 | 작업 | 완료 증거 |
| --- | --- | --- |
| R0 | 원천 데이터·달력·기존 구독 동의·메일 운영 설정 점검 | 확보/미확보 항목, 호출 비용과 생성 시간 기록 |
| R1 | 시황 생성·저장·목록·상세 | 동일 거래일 재현, 날짜 전환, 부분 실패·휴장·DST 테스트 |
| R2 | 기존 종목 보고서 확장 | 소유권/과거 버전 호환, 생성 중복·실패 복구, 근거 연결 확인 |
| R3 | 구독·해지·발송 대기열 | 동의/철회, 종목 선택, 중복 선점·재시도·반송 테스트 |
| R4 | 테스트 메일함으로 종단 검증 | 웹/메일 동일 보고서, 모바일/다크모드/이미지 차단, HTML/텍스트 링크 확인 |
| R5 | 제한된 운영 도입 | 검증된 수신자 대상 전달 결과, 모니터링·중지·롤백 확인 |

추가 검증 시나리오: 요청 중복/프로세스 재시작, 필수 자료 미수신, 다른 날짜 자료 혼합, 일시 메일 장애, 응답 유실, 발송 대기 중 해지, 계정 비활성화·주소 변경, 타인 보고서 ID 접근, 뉴스 HTML 삽입, 반송 후 재발송 억제. 발행 성공률·준비 지연·대기열 적체·중복 발송·접수/전달/반송률을 각각 관측한다. 추적 픽셀을 통한 열람률 수집은 초기 범위에 넣지 않는다.

## 구현 전에 확정할 결정

1. 미국장 마감 기준을 초기 대상으로 할지, 국내장 보고서도 별도로 포함할지.
2. 시황 공개 열람 범위와 기존 개인 종목 보고서의 로그인 정책.
3. 08:00 KST 기본 발송, 당일 지연 재시도 마감 시각, 휴장일 정책.
4. 종목 구독 수 제한, 일일 통합 메일과 유형별 메일 중 기본 구성.
5. 기존 SMTP 유지 또는 상태 추적이 가능한 메일 제공자 도입과 비용 상한.
6. 보고서·발송 이력 보존 기간과 정정 알림 정책.

AI 서술이 필요해지면 별도 단계에서 도입한다. 원천 수치의 계산 주체는 바꾸지 않고 근거 밖 추론·수치 변형·민감정보 전송을 검증하며, 생성 실패 시 규칙 기반 요약으로 대체한다.
