# R1b 시황 보고서 저장·조회

- 구현/검증일: 2026-10-23 KST
- 연결: [전체 계획](MarketBoard_Report_Mail_Plan.md), [R1a 데이터 계약](MarketBoard_Report_Mail_R1a.md)

## 사용자 흐름

대시보드 ‘오늘의 시황 보고서’ → 최근 발행 현황 → `/market-reports` 날짜별 목록 → `/market-reports/{id}` 상세를 제공한다. 메뉴에서도 진입할 수 있다. 시황은 비로그인 읽기가 가능하며 기존 `/api/reports` 개인 종목 보고서는 그대로 소유자 인증을 요구한다.

상세에는 발행 시각(KST), 대상 미국장 거래일, 실제 폐장 시각, 부분 자료 안내, 근거 섹션으로 연결되는 요약, 지수·섹터·시장 폭·거시·심리·뉴스, 출처/시점/이용 고지가 있다. 프런트엔드는 서버가 저장한 계산 결과를 표시한다.

## 생성·저장 계약

- `V48__create_market_reports.sql`: 불변 payload와 발행 시각·시장·거래일·버전·상태 저장. `(market, trading_date, report_version)` UNIQUE 제약으로 다중 인스턴스 중복 생성을 막는다.
- 현재 생성 대상은 직전 완료 미국장, 버전 1이다. 기존 발행본이 있으면 자료를 다시 수집하지 않고 기존 ID를 반환한다. 개인 보고서를 재사용하지 않는다.
- 외부 조회는 저장 트랜잭션 밖에서 수행한다. 저장 충돌 시 별도 트랜잭션 종료 후 먼저 저장한 보고서를 조회한다. 발행된 행을 수정하는 API는 없다.
- SPX/IXIC/RUT의 완료 거래일·직전 거래일 종가, 출처, 수집 시각을 필수로 검증한다. 필수 자료가 없으면 `DELAYED`로 반환하며 발행 행을 만들지 않는다.
- 섹터/시장 폭은 대상 거래일과 맞는 자료만 포함한다. 보조 자료 누락·기준일 미확인은 `checks`에 저장하고 `PARTIAL`로 발행한다. 현재 거시·심리의 마감 확정은 검증되지 않아 확인 문구와 PARTIAL 상태를 유지한다.
- 지수 수익률은 미국 세션 달력의 1/5/21세션 전 날짜와 비교한다. 거시 지표도 같은 비교 날짜를 사용하되 자산별 마감 시간 차이를 명시한다. 금리는 금리 수준의 상대 변화율이며 bp 변화가 아니다.
- 뉴스는 직전 거래일 현지 자정부터 대상 거래일 마감까지의 발행분만 포함한다. 제목(공백/대소문자 정규화)·URL 중복을 제거하고 http/https 원문 링크만 최대 10개 저장한다. 가격 변화와 인과관계를 추정하지 않는다.
- 조회·새로고침·서버 재시작은 보고서를 만들지 않는다. 기본 매일 08:40 UTC(17:40 KST)에 한 번 시도한다. 현재 08:30 UTC 지수 갱신 일정 뒤에 배치한 시간이며, 실제 자료 준비 여부는 생성 서비스에서 검증한다. DELAYED일 때만 완료 시점으로부터 30분 간격으로 최대 2회 재시도한다. PUBLISHED/EXISTING이면 즉시 종료하고, 예상치 못한 예외는 로그를 남긴 뒤 단기 재시도하지 않는다. `MARKET_REPORT_CRON` 또는 `market-report.cron`으로 주기를 변경하거나 `-`로 정기 실행을 끌 수 있다. 기존 메일 스케줄과 연결하지 않는다.
- 재시도 예약은 프로세스 메모리에만 존재한다. 서버가 재시작되면 예약은 사라지며 다음 일일 일정 또는 관리자 수동 생성으로 진행한다. 여러 인스턴스에서 실행하더라도 발행본 중복은 DB UNIQUE 제약으로 막지만 시도 자체는 인스턴스별로 실행된다.

## API

| 메서드/경로 | 권한 | 동작 |
| --- | --- | --- |
| `GET /api/market-reports?before=YYYY-MM-DD` | 공개 | 지정 거래일 이하 최신 30개, 날짜 내림차순. 목록 화면에서 이전 구간 조회 가능 |
| `GET /api/market-reports/latest` | 공개 | 새 달력 판별과 마지막 발행본을 비교해 CURRENT/DELAYED/UNAVAILABLE 반환. 미발행 중에도 기존 보고서 표시 |
| `GET /api/market-reports/{id}` | 공개 | 저장된 발행본만 반환, 라이브 자료 재조회 없음 |
| `POST /api/admin/market-reports/generate` | ADMIN | PUBLISHED/EXISTING/DELAYED 및 사유 반환 |

## 검증 증거

- Java 15개 통과: 신규 시황 서비스 7개, 권한 3개, 기존 개인 보고서 5개. 불변 재조회, 동시 생성, 날짜 전환·누락·달력 장애, 뉴스 중복/위험 링크/미래 기사 제외, 공개 읽기/관리자 쓰기 분리 포함.
- 프런트 TypeScript·대상 ESLint 통과. Docker frontend/backend 프로덕션 빌드 성공.
- 로컬 MySQL V48 적용, 서버 시작 시 2026-10-22 미국장 보고서 ID 1 생성. 지수 3개·섹터 11개·거시 5개·뉴스 10개, 확인 사항 2개(시장 폭 미확보, 거시/심리 기준 시각 주의), PARTIAL.
- 실제 HTTP 날짜 필터 `before=2026-10-21`은 빈 배열. 비인증 생성 요청은 401.
- 백엔드 재시작 후에도 보고서 ID 1 한 건 유지. 상세 응답 SHA-256 `2020d7a4fccf22c65cd9ff443e2636d623f8d01934ef365420141a8b3c5311f4`가 재시작 전후 일치함을 확인했다.
- 브라우저 목록→상세 이동, 키보드 날짜 필터의 빈 목록, 최신 목록 복귀 확인. 320px에서 문서 clientWidth/scrollWidth=305/305, 섹터 표만 내부 스크롤(271/658).

## 남은 범위

### 생성 주기 후속 수정

사용자 요청에 따라 매시간 실행 및 시작 이벤트를 제거했다. 일일 시도와 조건부 재시도만 유지하며, 스케줄러 테스트로 30분 간격·최대 2회·성공/기존 보고서 시 중단·예외 시 중단·시작 리스너 제거를 검증한다. 위 최초 생성/재시작 증거는 이전 시작 시 생성 정책으로 수집한 기록이다.

후속 수정 검증: 스케줄러 5개·시황 서비스 7개·권한 3개, 총 15개 테스트 통과. Docker 백엔드 재빌드 및 로컬 적용 완료. 실제 30분 대기는 수행하지 않고 예약 시각과 콜백 실행 횟수를 테스트에서 검증했다.

운영 배포·메일 발송·실기기/스크린리더 검증은 하지 않았다. 브라우저는 기존 로그인 상태를 유지했으며 비인증 API는 별도로 검증했다. 새 거래일의 발행 지연 사유는 생성 응답/서버 로그로 확인하고, 공개 최신 조회는 지연 여부만 안내한다. 영속 작업 이력·정정 버전 발행·메일 대기열은 후속 단계다. 현재 공개 데이터의 이용/재배포 조건과 운영 정책은 R0의 미확인 항목으로 유지한다.
