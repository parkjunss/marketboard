# 포트폴리오 설계 — General

작성: 2026-10-18. 상태: 설계 초안, 구현 완료 아님.

## 문제와 목적

현재 ETF 화면은 고정 월말 전략의 지표와 검토 기록을 보여주지만 사용자가 가진 돈을 어떻게 배분할지 비교하기 어렵다. 주 흐름을 투자금과 후보 자산 입력 → 위험·수익과 배분안 비교 → 배분 금액 확인으로 바꾼다. 사용자가 선택하며 자동 주문은 하지 않는다.

## 화면 방향

전용 메뉴는 포트폴리오 설계로 발전시킨다. 기본 화면은 조건과 결과이며, 기존 월말 ETF 모멘텀은 비교 전략, 검토 기록과 모의 운용은 후속 기능으로 둔다. 기존 /etf 주소와 저장 기록은 유지한다.

후보 자산은 사용자 선택으로 확정했다: SPY·QQQ·EFA·EEM·IEF·GLD 6종을 기본값으로 제공하고, 사용자가 주식·ETF를 직접 추가하거나 제외한다. 미국 USD 표시 자산, 공매도·레버리지 없는 배분부터 다룬다. USD 투자금으로 시작하며 원화 환산을 묵시적으로 적용하지 않는다.

효율적 투자선은 선택한 자료와 제약에서 계산한 평균–분산 모델이다. 미래 수익 예측이나 보장으로 표시하지 않는다. 현재 조건의 설계 분석과 월말 모멘텀의 과거 신호는 서로 다른 기준일로 구분한다.

## 재사용과 신규 범위

- 기존: price_history 일봉, Python 계산/Spring 인증/프론트 표시 구조, ScatterChart, 백테스트, 검토 기록·모의 운용.
- 신규: 동일 기간 자산별 수익률 정렬과 공분산, 제약 최적화, 효율적 투자선 선택, 투자금별 배분 명세.
- 기존 개별 종목 EWMA 변동성을 포트폴리오 공분산 계산에 혼합하지 않는다.
- 기존 _load_closes는 결측 날짜를 먼저 제거하므로 품질 진단 없이 그대로 최적화에 연결하지 않는다.

## 사용자 여정

새 투자자는 투자금과 후보 자산으로 시나리오를 비교한다. 기존 보유자는 이후 보유 비중 대비 변경액을 비교한다. 데이터 부족 사용자는 가능한 개별 지표와 제외 사유를 보고 기간·종목을 직접 조정한다. 운영자는 누락 종목과 기간을 확인해 수집을 복구한다. 검토 저장·모의 운용은 결과 확인 이후 선택적으로 진행한다.
