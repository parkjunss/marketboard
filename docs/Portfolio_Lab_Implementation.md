# 포트폴리오 설계 구현 — 2026-10-18

## 구현된 사용자 흐름

`/etf`를 포트폴리오 설계 화면으로 확장했다. ETF 6종 기본값, 직접 티커 추가·제외(2~10종), 기간·투자금·남길 현금·전체 자금 기준 종목 상한·위험 한도·샤프 비교용 무위험 수익률을 입력한다.

개별 관측 지표와 데이터 상태, 공통 구간 상관관계, 동일 비중·최소 분산·위험 한도 내 수익 추정 최대 후보, 21점 제약 효율적 투자선을 표시한다. 차트 점 또는 선택 상자로 후보를 고르면 배분 비중·USD 금액·최근 저장 일봉 기준 정수주 참고 수량·잔액이 함께 바뀐다. 4일보다 오래된 가격으로는 수량을 계산하지 않는다. 조건 변경이나 재계산 실패 시 이전 결과임을 명시한다.

기존 월말 ETF 모멘텀·검토 저장·모의 운용은 접힌 보조 영역으로 보존했다. 신규 최적화 결과를 기존 ETF 고정 전략 저장·모의 운용에 전달하는 기능은 포함하지 않는다. 스크리너에서 ETF 패널은 제거했다.

## 코드 경로

- `frontend/src/components/portfolio/PortfolioDesigner.tsx`: 입력·상태·차트·배분 표시. 서버 수치를 표시하며 금융 계산은 하지 않는다.
- `POST /api/portfolio/design`: Spring `PortfolioDesignController` 인증과 입력 검증 → `CollectorClient`.
- `POST /portfolio/design`: FastAPI Pydantic 검증 → `collector/app/portfolio_lab.py`.
- 저장된 `price_history` 일봉을 읽으며 수집·DB 쓰기를 수행하지 않는다. 기존 ETF 일봉 로더에 선택 티커를 전달한다.
- SciPy의 SLSQP로 제약 최소분산과 위험 한도 문제를 풀고, HiGHS 선형 계획으로 가능한 수익률 상한을 구한다. 임의 산점도를 투자선으로 표시하지 않는다.

## 계산과 부분 실패

연환산 표본 평균·공분산은 252 기준이다. 현금은 고정 비중·수익률 0%이며 무위험 수익률은 샤프에만 사용한다. 수익 추정치는 CAGR 또는 미래 수익 예측이 아니다. 차트의 개별 자산도 최적화와 같은 공통 구간을 사용한다.

달력 평일 간격이 1인 관측 쌍만 일간 수익률로 사용하고, 동일한 시작·종료일 쌍으로 자산들을 정렬한다. 주말은 포함할 수 있지만 거래일 누락으로 생긴 여러 날 수익률은 하루 수익률로 계산하지 않는다. 공식 거래소 캘린더 대신 보수적인 평일 검사를 사용하므로 공휴일을 낀 정상 구간도 제외될 수 있다. 화면에 이 한계를 표시한다.

최적화는 공통 유효 수익률 60개 이상이 필요하다. 부족 종목을 자동 제외하지 않으며 개별 지표는 보존한다. 특이 공분산, 불가능 상한, 수렴 실패는 구별한다. 위험 한도만 불가능하면 다른 후보와 경고를 함께 표시한다. 전액 현금은 가격 자료가 없어도 표시 가능하다.

## 검증과 남은 범위

- Python: 신규 설계 13개 및 기존 ETF 관련 59개 테스트 통과. 2자산 해·비중 제약·금액 합·공백 구간·부분 데이터·특이 공분산·전액 현금·참고 수량·오래된 가격을 검사한다.
- Spring: `PortfolioDesignControllerTest` 통과. 인증, 잘못된 현금, 중복 티커, 부분 응답, 서버 장애를 검증한다.
- TypeScript, 변경 영역 ESLint, Next.js 프로덕션 빌드 통과. 최초 빌드는 샌드박스의 정적 출력 디렉터리 생성 권한 오류로 중단됐으며, 권한을 확보한 재실행은 성공했다.
- 실제 DB와 로그인 브라우저 검증은 로컬 Docker 엔진이 실행되지 않아 미수행. 생산 데이터의 조정 일관성·최신성은 미확인.
- 커밋·푸시·운영 배포는 하지 않았다. 실제 주문과 보유 수량은 변경하지 않는다.
