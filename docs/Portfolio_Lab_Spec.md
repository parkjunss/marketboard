# 포트폴리오 설계 — Spec

## 2026-10-18 사용자 수정: 기간 수익률 (기존 연환산 평균 명세 대체)

- 수익률의 연환산 산술평균을 제거한다. 공통 관측 기간 시작·종료 종가로 `(종료/시작-1)×100`을 계산한다. 누락 구간을 건너뛴 가격 변화도 이 기간 수익률에는 포함된다.
- 후보의 `periodReturnPct`는 기간 초 전체 자금 기준 비중으로 매수 후 보유한 가중 기간 수익률이다. 현금 수익률은 0%. 개별 표는 각자 실제 관측 기간, 차트는 공통 기간이며 날짜를 표시한다.
- 공분산·변동성은 기존 연환산 척도를 유지한다. 기간 수익률과 단위가 다른 무위험 수익률·샤프 입력 및 출력을 제거한다.
- 경계는 미래 기대수익의 효율적 투자선이 아닌 동일 과거 기간 수익률–연환산 변동성의 제약 경계로 표시한다. 기간 초 비중 기준의 고정 비중 위험 모형이며, 매수 후 비중 변화를 반영한 실제 보유 경로의 변동성은 아니다.
- 아래 기존 명세 중 평균 수익률·무위험 수익률·샤프 정의는 이 수정으로 대체한다. 계산 버전은 `portfolio-lab-v2-period-return`이다.

상태: 구현 전 계산·수용 기준. API 이름과 최적화 라이브러리는 구현 시 기존 계약과 비교해 확정한다.

## 데이터와 날짜

- 후보 기본값은 SPY·QQQ·EFA·EEM·IEF·GLD다. 사용자 선택 주식·ETF 목록을 서버에 전달하며, 최적화 종목군을 기존 ETF_UNIVERSE 상수로 고정하지 않는다. 기존 월말 모멘텀 비교 전략의 고정 6종 규칙은 유지한다.
- 티커는 공백 제거·대문자 정규화 후 중복을 제거한다. 서버에서 지원 여부와 가격 이력을 검사하고, 미등록·데이터 부족 종목을 응답에 명시한다. 사용자가 선택한 종목을 조용히 제외하지 않는다.
- 분석 기간은 사용자 선택 기간, 기본 종료일은 뉴욕 기준 최근 완료 일자다. 실제 사용한 마지막 거래일을 별도 표시한다.
- 월말 ETF 신호와 달리 설계 분석은 지난 월말로 강제 절단하지 않는다.
- 일봉은 DB에서 읽으며 데이터 공급자·가격 조정 상태를 결과에 명시한다. 확인되지 않은 가격 수익률을 배당 포함 총수익률로 부르지 않는다.
- 자산별로 날짜 정렬·중복·유한 양수 가격을 검사한다. 현금 가격으로 결측을 채우지 않는다.
- 수익률은 모든 자산에서 동일한 시작일·종료일을 가진 구간으로 정렬한다. 중간 누락으로 만들어진 여러 거래일 수익률을 1일 수익률로 연율화하지 않는다. 공통 표본 선정 전에 누락 진단이 필요하며 거래일 판정 방식은 구현 시 명시한다.
- 지표마다 유효 관측 수와 사용 기간을 반환한다. 초기 최적화 최소 표본은 60개 공통 일간 수익률로 두고, 부족하면 개별 지표를 유지하면서 최적화만 미제공한다.

## 계산

- 일별 단순 수익률 r, 연환산 평균 μ = mean(r) × 252, 공분산 Σ = sample_cov(r) × 252.
- 포트폴리오 수익 추정치 = wᵀμ, 변동성 = sqrt(wᵀΣw). 누적 수익률·CAGR과 구분한다.
- 위험자산 내부 비중 합 1, 각 비중 0 이상, 전체 자금 기준 자산별 상한 준수. 현금 비중 c를 고정 입력하면 전체 자금 기준 위험자산 비중은 (1-c)w다.
- 전체 자금 수익 추정치 = (1-c)wᵀμ + c × 현금 수익률 가정, 변동성 = (1-c)sqrt(wᵀΣw). 현금 수익률과 샤프 계산용 무위험 수익률의 의미를 명시한다.
- 효율적 투자선: 제약 내 최소 분산점에서 시작해 목표 수익별 최소 분산 문제를 푼 상단 경계. 무작위 포트폴리오 산점도를 효율적 투자선으로 부르지 않는다.
- 최적화 성공 상태와 제약 잔차를 검사한다. 불가능 조건·수렴 실패·특이 공분산을 숨기거나 임의 비중으로 대체하지 않는다. 소수점 오차 허용범위를 정해 검증한다.
- 투자금은 주어진 비중의 배분 금액을 결정하며, 동일 조건에서 투자금만 바뀌면 위험·수익 추정치와 비중은 변하지 않는다.
- 참고 수량은 최신 완료 일봉 가격으로 계산하며 가격일을 표시한다. 정수주 계산 시 내림 처리한 잔액은 현금에 합산한다. 실제 체결 가격으로 표시하지 않는다.

## 서버와 UI

금융 계산·배분 금액·반올림 처리는 Python 서버 한 곳에서 수행한다. Spring은 인증과 입력 검증 및 결과 전달을 담당한다. 프론트는 조건 입력, 후보 선택, 시각화와 상태 표시를 담당한다. 기존 ScatterChart의 기간 수익률 축을 무조건 재사용하지 않고 연환산 수익률로 명확히 구분한다.

응답은 사용 조건, 데이터 진단, 개별 지표, 후보별 비중·배분, 투자선 점, 경고와 계산 버전을 담는다. 네트워크 실패, 데이터 부족, 불가능 제약, 수렴 실패를 서로 다른 상태로 보여준다.

## 검증 기준

- 알려진 2자산 해와 계산 비교, 상관관계에 따른 분산 효과 확인.
- 비중 합·현금 포함 금액 합·상한·음수 금지, 투자금 배수에 따른 배분 일관성 검증.
- 투자선 상단 경계·목표 제약·수렴 검사 및 불가능 조건 재현.
- 결측·중복·부분 이력·비정상 가격·전부 현금·동일 자산 입력 처리.
- 데이터 부족에도 가능한 개별 지표가 화면에 남는지 검증.
- 실제 데이터에서 입력 → 계산 → 차트 후보 선택 → 배분 표 일치, 모바일과 키보드 선택, API 장애 표시 확인.
- 같은 표본으로 최적화하고 그 표본에서 얻은 성과는 표본 내 결과로 표시한다. 미래 성과 또는 검증된 투자 우위로 주장하지 않는다.

## 구현 순서

1. 데이터 진단과 자산별 비교·투자금 입력의 세로 흐름.
2. 최소 분산·제약 효율적 투자선 서버 계산과 결정적 테스트.
3. 후보 선택 차트와 현금 포함 금액·수량 표, 실제 데이터 브라우저 검증.
4. 검토 저장·기존 월말 모멘텀 비교·모의 운용 연계.
