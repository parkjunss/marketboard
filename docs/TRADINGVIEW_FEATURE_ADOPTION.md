# TradingView 참고 기능 도입 계획

작성일: 2026-10-14 · 상태: 우선순위 초안, P0-1 봉 정보 표시 1차 구현

## 1. 방향과 근거 (General)

MarketBoard 사용자가 종목을 찾고, 가격 흐름을 분석하고, 자신의 판단 근거를 표시하고, 다음 방문에서 분석을 이어갈 수 있도록 차트 사용성을 개선한다. 차트에서 얻은 근거를 기존 관심종목·알림·투자 검토·보고서 흐름으로 연결하는 것이 목적이다.

이 문서는 저장소 확인과 도입 제안을 바탕으로 작성했으며, 2026-10-14 REA로 공개 AAPL 차트의 도구 모음·추세 도구·시간봉·지표 템플릿·비로그인 저장 동작을 관찰했다. 근거와 미확인 범위는 [TRADINGVIEW_REA_ANALYSIS.md](TRADINGVIEW_REA_ANALYSIS.md)에 기록했다. 십자선 이동·드로잉 편집·로그인 복원 등은 추가 관찰 후 동작 규칙을 확정한다.

2차에서 포인터 이동에 따른 OHLC·등락 범례 갱신을 확인하고 MarketBoard에 봉 정보 표시를 추가했다. 수평선·추세선은 차트 클릭 시 가입 안내가 나타나 실제 편집 동작은 미확인이다. P0-1 중 활성 지표의 선택 봉 값 표시는 남아 있고, P0-2 이후 기능은 구현 전이다.

현재 확인한 재사용 기반:

- `frontend/package.json`: `lightweight-charts ^5.2.0` 사용.
- `frontend/src/components/CandleChart.tsx`: 캔들·거래량 시리즈와 SMA·EMA·볼린저밴드·RSI·MACD·ATR·상대 거래량 계산 및 표시 기반.
- `frontend/src/app/(app)/symbols/[ticker]/page.tsx`: 종목 상세 차트, 기간 전환, 지표 설정 연결.
- `frontend/src/lib/api.ts`: 차트 지표 설정 조회·저장 API 함수.
- `docs/TECHNICAL_INDICATORS.md`: 지표 계산·결측·워밍업 규칙.

새 지표를 대량 추가하기보다 이미 있는 정보를 읽기 쉽고 재사용하기 쉽게 만드는 작업부터 진행한다. 기존 설정 저장이 어느 범위까지 복원되는지는 구현 착수 시 API·화면을 함께 확인한다.

## 2. 가져오면 좋은 기능과 우선순위 (Function)

| 순서 | 기능 | 해결하는 사용자 문제 | 최소 도입 범위 | 난이도 예상 |
|---|---|---|---|---|
| P0-1 | 십자선 상세 정보 | 특정 봉의 가격과 지표를 정확히 읽기 어려움 | 선택 봉 날짜·OHLC·등락률·거래량·활성 지표 값, 포인터가 없으면 최신 봉 | 낮음~중간 |
| P0-2 | 전체화면과 보기 초기화 | 좁은 화면에서 분석하거나 확대 후 원래 구간으로 돌아오기 어려움 | 전체화면 진입·종료, 최근 구간 복귀, 전체 데이터 보기 | 낮음 |
| P0-3 | 수평선·추세선 | 지지·저항 가격과 추세를 직접 표시할 수 없음 | 수평선 1점, 추세선 2점 생성, 선택·이동·삭제·취소 | 중간~높음 |
| P0-4 | 종목별 분석 상태 저장 | 재방문할 때 분석을 다시 해야 함 | 드로잉, 시간봉, 표시 구간 복원; 기존 지표 저장 재사용 | 중간 |
| P1-1 | 가격 구간 측정 | 상승 여력·손실 범위·기간을 따로 계산해야 함 | 두 지점 사이 가격 차이·변동률·봉 수 표시 | 중간 |
| P1-2 | 지표 템플릿 | 여러 종목에서 같은 설정을 반복함 | 현재 지표 조합을 이름으로 저장·적용·삭제 | 중간 |
| P1-3 | 차트에서 가격 알림 만들기 | 분석한 가격을 알림 화면에 다시 입력함 | 선택 가격으로 기존 알림 생성 폼 열기, 조건 확인 후 저장 | 중간 |
| P1-4 | 차트 근거를 투자 검토·보고서에 연결 | 차트와 판단 기록이 분리됨 | 종목·시간봉·기준 시점·분석 메모 연결; 이미지 저장은 별도 검토 | 중간 |
| P2-1 | 사각형 가격 구간·피보나치 | 선 하나로 표현하기 어려운 구간 분석 | 기존 드로잉 선택·편집·저장 구조 위에 추가 | 중간~높음 |
| P2-2 | 비교 종목·지수 | 종목 단독 상승과 시장 대비 강세를 구분하기 어려움 | 동일 시작점을 0%로 정규화해 비교, 데이터 없는 구간 명시 | 중간~높음 |
| P2-3 | 다중 차트 | 종목·시간봉을 반복해서 전환함 | 우선 2개 차트, 필요 시 십자선·시간 구간 동기화 | 높음 |
| P2-4 | 과거 봉 재생 | 미래 가격을 보지 않고 판단을 연습하기 어려움 | 선택 시점 이후 봉 숨김, 한 봉씩 진행, 지표도 공개된 봉만 계산 | 높음 |

난이도는 설계 추정이며 일정 약속이 아니다. P0는 권장 순서이고 한 번에 모두 구현할 필요는 없다. 기존 기능이 이미 같은 요구를 충족하면 그 항목은 개선만 하거나 생략한다.

## 3. 사용자 여정과 필수 규칙 (Spec)

### 3.1 첫 방문: 종목을 찾고 차트를 읽는다

- 초기에는 기존 차트를 즉시 표시한다. 저장 설정 조회 실패가 차트 조회를 막지 않는다.
- 십자선의 정보는 선택한 봉과 일치해야 한다. 지표 워밍업 부족·거래량 결측은 `—`로 표시하고 0으로 대체하지 않는다.
- 날짜·시간 표기에는 시간대 규칙을 통일한다. 일봉 거래일과 장중 시각을 혼동하지 않는다.
- 차트 이동·확대 동작을 유지하고, 보기 초기화 버튼은 드로잉 삭제와 분리한다.
- 모바일에서는 탭으로 봉 정보를 읽고 도구를 명시적으로 선택한다. 키보드로도 도구 선택·취소·삭제와 전체화면 종료가 가능해야 한다.

### 3.2 분석: 선을 그리고 수정한다

- 일반 이동 모드와 드로잉 모드를 구분한다. 드로잉 중에는 같은 입력이 차트 이동으로 처리되지 않도록 한다.
- 선 좌표는 화면 픽셀이 아니라 시간·가격으로 저장한다. 확대·크기 변경 후에도 같은 분석 위치에 표시한다.
- 추세선 생성 중 Esc 또는 취소 버튼을 누르면 미완성 선만 취소한다.
- 선택한 선만 삭제하며, 전체 삭제는 별도 확인을 받는다. 1차에는 임의 도형·자동 추세선 추천을 추가하지 않는다.
- 가격 축 변경·시간봉 전환 시 선 표시 규칙을 정의한다. 우선 선은 종목과 시간봉별로 분리한다.

### 3.3 재방문: 분석을 이어간다

- 저장 범위는 사용자·종목·시간봉으로 구분한다. 다른 사용자의 분석 데이터에 접근할 수 없어야 한다.
- 로그인 사용자는 서버 저장을 우선한다. 비로그인 사용자에게는 현재 세션 사용을 제공하고 지속 저장 제한을 명시한다.
- 기존 지표 설정 API를 확인한 후 확장 또는 별도 드로잉 저장을 선택한다. 종목별 선과 공통 지표 템플릿의 저장 범위를 섞지 않는다.
- 저장 상태를 저장 중·저장됨·실패로 표시한다. 저장 실패 시 현재 편집 결과를 유지하고 재시도를 제공한다.
- 봉 데이터가 바뀌어 저장 구간을 복원할 수 없으면 최근 구간을 표시하고 사용자에게 알린다.
- 다중 탭 편집은 버전 검증 등 기존 프로젝트의 동시성 규칙을 확인한 후 적용한다.

### 3.4 행동: 알림과 판단 기록으로 연결한다

- 차트 가격에서 알림 폼을 열면 종목·가격을 채우되, 기존 알림 검증과 사용자 확인을 거쳐 생성한다.
- 기존 알림 서비스가 지원하는 조건부터 연결한다. 선 돌파·지표 교차 알림은 지원 여부를 확인한 후 별도 범위로 정한다.
- 투자 검토·보고서에는 분석 시점과 가격 자료 기준을 남긴다. 차트 표시를 자동 매매 판단으로 취급하지 않는다.

## 4. 권장 구현 단위

1. **읽기 개선:** 십자선 정보와 전체화면·보기 초기화. 기존 차트를 사용하는 종목 상세·대시보드·백테스트 화면의 영향을 확인한다.
2. **분석 표시:** 수평선·추세선 생성·편집·삭제를 종목 상세 화면에 적용한다.
3. **분석 복원:** 사용자별 드로잉·시간봉·표시 구간 저장과 실패 복구를 연결한다.
4. **작업 연결:** 실제 사용 피드백에 따라 가격 측정·템플릿·알림·투자 검토 연결을 선택한다.

공용 `CandleChart`의 기존 호출자는 읽기 개선을 공유할 수 있으나, 드로잉·저장 UI는 우선 종목 상세에만 제공한다. 구현이 확정되면 `GENERAL.md`, `FUNCTION.md`, `SPEC.md`의 관련 항목과 실제 기능 상태를 함께 갱신한다. 이 초안의 제안을 구현 완료 상태로 기록하지 않는다.

## 5. 구현 전 확인과 완료 기준

- 참고할 TradingView 공개 차트 화면에서 도구 선택·생성·편집·삭제·복원의 실제 동작을 확인한다.
- 설치된 Lightweight Charts 버전의 좌표 변환·십자선·primitive API와 라이선스·표시 의무를 확인한다.
- 데이터 공급원의 시각·수정주가·장중 봉 갱신 정책을 확인한다. 차트 기능 개선과 가격 데이터 품질을 구분한다.
- 포인터 이동·터치·키보드·테마 전환·창 크기 변경·전체화면 종료를 확인한다.
- 빈 데이터·결측·시간봉 변경·종목 변경·로그아웃·저장 실패에서도 잘못된 봉 정보나 다른 종목의 선이 표시되지 않아야 한다.
- 저장 기능은 재로그인·재방문 복원과 다른 사용자 접근 차단을 검증한다.
- 큰 봉 배열·여러 지표에서도 포인터 이동마다 차트 전체를 재생성하지 않아야 한다.

## 6. 보류 항목과 적용 방식

Pine Script 호환 엔진, 전체 지표 라이브러리, 브로커 주문 연동, 커뮤니티·공유 마켓은 이번 우선 도입 범위에서 보류한다. 유지보수·검증 부담에 비해 현재 MarketBoard의 분석 여정을 개선하는 효과가 먼저 확인되어야 한다.

공개 동작을 참고해 기존 코드와 공식 라이브러리 API로 구현한다. TradingView의 제품 화면·소스·자산을 사용하는 경우 적용 가능한 이용 조건을 확인한다. Advanced Charts 등 별도 제품 도입은 라이선스와 데이터 공급 계약을 확인한 뒤 독립적으로 결정한다.
