# ADR 0002: 투자 계산은 서버가 소유한다

- 상태: 승인 — 사용자 지시, 2026-10-16
- 적용 대상: 투자 지표, 전략 신호/순위, 배분, 위험 판단, 성과 계산

## 결정

투자 계산과 판단 규칙은 백엔드에서 실행한다. 프론트엔드는 입력 수집, API 조회, 화면 상태 관리와 결과 표시만 담당한다.
Next.js 서버 컴포넌트나 route handler로 계산 위치만 바꾸는 것은 이 원칙의 이행이 아니다.

- Python Collector: 시계열·퀀트 계산의 단일 구현. 화면·백테스트·모의 운용은 같은 규칙을 호출한다.
- Spring Boot: 인증·인가, 입력 검증, 기존 원장/업무 규칙, Collector 호출 및 API 응답. Python 계산을 다시 구현하지 않는다.
- Frontend: 서버가 반환한 기준일, 순위, 비중, 상태, 근거를 표시한다. 원시 일봉으로 신호를 재계산하거나 서버 실패 시 로컬 계산으로 대체하지 않는다.
- 날짜/숫자/통화/퍼센트 포맷과 화면 배치는 표시 로직으로 허용한다. 전략 기준일 산정, 결측 처리, 지표 계산, 순위 결정, 임계값 판단은 서버 책임이다.
- `null`과 사유를 보존한다. 서버 장애와 데이터 부족을 분리하며 실패를 0% 또는 현금 100%로 대체하지 않는다.

## 이유

브라우저 시각·버전·부분 데이터에 따라 투자 판단이 달라지는 것을 방지한다. 계산 규칙을 서버 테스트로 검증하고, 이후 저장·재현·백테스트에서 재사용한다.

## 이번 적용 범위

ETF 모멘텀 패널을 Collector 계산 → Spring 인증 API → Frontend 표시 구조로 이관했다.
프론트엔드 ETF 계산 모듈과 계산 테스트는 삭제하고 Python으로 옮겼다.
기존 다른 기능의 프론트엔드 투자 계산이 전부 이관됐다는 뜻은 아니다. 예를 들어 `investment-review-insights.ts`의 위험 판단은 후속 이관 대상이며, 해당 기능을 수정할 때 서버로 옮긴다. 새 투자 계산은 프론트엔드에 추가하지 않는다.
