# MarketBoard 주간·월간 투자 판단 지원 계획

작성: 2026-09-10 · 기준 코드: `0948db9` · 상태: 계획, 제품 코드 미변경

> 개발 기준 문서: 루트의 [GENERAL](../../GENERAL.md) / [FUNCTION](../../FUNCTION.md) / [SPEC](../../SPEC.md). 본 문서는 설계 배경과 로드맵 참고 자료로 유지하며, 상세 규격이 충돌하면 루트 세 문서를 우선한다.

## 1. 방향 변경

확정 핵심 가치: **실제 투자에 도움이 되는 시장 상황 파악과 체계적 판단**. MarketBoard를 시장 변화와 내 규칙을 함께 검토하고, 사용자가 직접 실행·보류·유지를 결정한 뒤 결과를 복기하는 개인용 투자 판단 지원 도구로 재편한다.

기존 [리팩토링 분석](INVESTMENT_WORKSPACE_PLAN.md)의 데이터·계산 오류·포트폴리오 원장 개선은 그대로 필요하다. 다만 종목 정보 탐색보다 전략 정의와 검증을 먼저 구현한다. 기존 계획의 단계 2는 아래 Q2로, 전략 체계화 단계 4는 Q1~Q3으로 앞당긴다. 원장은 모의 운용 단계부터 붙이고, 자유 대시보드와 재무 화면 확장은 뒤로 미룬다.

확정 요구사항: 주 1회 또는 월 1회 거래 검토, 자동 주문 없음, 이메일·모바일 알림으로 점검 결과 전달. 기본 사용 흐름은 **주간 시장·위험 점검 + 월간 리밸런싱 검토**이며 전략별 검토 주기는 주간/월간으로 선택한다. 점검할 때마다 거래하지 않으며 '유지'도 정상 결과다.

개발 가정: 미국 주식·ETF, 확정 일봉, 롱온리·무레버리지부터. 거래 시장·첫 자산 목록·규칙 수치·알림 요일과 시각·모바일 전달 방식은 구현 전 정한다. 자동 주문 여부를 다시 묻거나 브로커 주문 연동을 개발 선행조건으로 삼지 않는다.

### 시장 맥락과 행동 규칙

| 축 | 우선 정보 | 사용자에게 설명할 것 |
|---|---|---|
| 추세 | 대표 지수/보유 자산의 중장기 추세 및 상대 성과 | 이전 점검 대비 변화와 추세의 지속/훼손 |
| 시장 폭 | 상승·하락, 추세 위 종목 비율, 신고가·신저가 | 일부 대형주만 움직이는지 시장 전체가 참여하는지 |
| 변동성 | 실현 변동성·낙폭, VIX는 보조 | 내 포트폴리오의 위험 노출 변화 |
| 금리·환율 | 대표 금리·USD/KRW 변화 | 보유 자산과 기준통화에 관련된 영향 |

각 정보는 **변화 → 해석 → 내 보유와의 관련성 → 확인할 조건**으로 구성한다. 기준일·원천·비교 기간을 함께 표시한다. 시장 설명만으로 자동 매수/매도 결론을 만들지 않고, 실제 행동 검토는 저장된 전략 조건의 충족 여부로 설명한다. 임의 종합 점수 대신 개별 근거와 상충하는 신호를 보여준다.

## 2. 지금 있는 것과 새로 필요한 것

| 현재 | 한계 | 새 역할 |
|---|---|---|
| BUY_AND_HOLD / SMA_CROSSOVER / PERIODIC_REBALANCE / VOLATILITY_TARGET | 주로 수익률 곡선 계산 함수. 전략 정의·체결·운용의 공통 계약 부족 | 검증용 대조 전략과 전략 템플릿 |
| 현재 S&P500 모멘텀 스크리너 | 최신 후보 탐색이며 과거 시점별 종목 선정 엔진이 아님 | 시점별 유니버스·랭킹·편입 규칙을 갖춘 선정 단계 |
| 몬테카를로·VaR·Hurst | 개별 분석 수치, 거래 규칙과 직접 연결되지 않음 | 위험·민감도 보조 분석. 기본 매수 점수에서 제외 |
| 포지션 수량·평단가 입력 | 현금·체결·전략별 손익 귀속 부족 | 원장 기반 모의/실제 계좌 읽기 모델 |
| 실시간 시세 구독 | 주문 상태나 데이터 신선도 보장은 아님 | 운용 화면의 참고 가격; 확정 일봉 신호와 구분 |

코드에서 확인한 월 경계 수익 누락과 누락 종목의 조용한 제외를 먼저 수정한다. 기존 39개 테스트 통과 기록은 이 오류를 부정하지 않는다. 이번 계획 갱신에서는 테스트를 다시 실행하지 않았다.

## 3. 전략을 저장하는 단위

전략 이름과 몇 개 숫자만 저장하는 대신, 다음을 버전으로 고정한다.

| 구성 | 설정할 내용 |
|---|---|
| 가설 | 어떤 현상을 이용하는가, 비교 대상과 실패 조건은 무엇인가 |
| 유니버스 | 고정 ETF 목록 또는 시점별 종목 집합, 유동성·거래 가능 조건 |
| 자료 | 빈도, 기준 시각·거래소 시간대, 가격 보정, 발표/가용 시각, 데이터 버전 |
| 선정·신호 | 지표, 필터, 순위, 편입/청산 조건, 최소 관측 수 |
| 포트폴리오 구성 | 동일비중/목표비중/변동성 기반 배분, 현금, 최대 종목·섹터 비중 |
| 실행 | 평가/리밸런싱 일정, 다음 거래일 체결 규칙, 정수/소수주, 최소 주문액 |
| 비용·위험 | 수수료·슬리피지, 매매 한도, 현금 이자, 거래 중단 조건 |
| 검증 | 벤치마크, 개발·검증 구간, 파라미터 범위, 통과 기준 |

전략 수정은 새 버전이다. 과거 실행이나 모의 운용 중인 규칙을 덮어쓰지 않는다. 초기 UI는 검증된 템플릿+제한된 설정 폼으로 만들고, 임의 Python 코드 실행이나 범용 시각 전략 편집기는 보류한다.

## 4. 첫 전략 묶음

전략 후보이지 성과가 검증된 추천은 아니다. 순서대로 엔진의 정확성을 확인하는 데도 사용한다.

1. **대조 전략**: 동일 자산 buy-and-hold와 고정 목표비중 정기 리밸런싱. 엔진 검산의 기준.
2. **ETF 추세·모멘텀**: 지정 ETF 집합에서 과거 수익률로 순위를 정하고 추세 조건을 통과한 상위 N개에 배분. 탈락분은 명시된 현금 규칙 적용. 초기 대표 전략으로 권장.
3. **이동평균 추세 전략**: 진입·청산 시점과 거래 비용을 명확히 한 기존 SMA 확장.
4. **변동성 목표 배분**: 추세 신호와 위험 배분을 분리. 기존 VIX 필터는 선택 기능으로 두고 데이터 의존성과 효과를 별도 비교.
5. **주식 횡단면 모멘텀/가치·퀄리티**: 과거 구성 종목·상장폐지·시점별 재무 가용성이 준비된 후 추가. 최신 재무 수치를 과거에 적용하지 않는다.

첫 대표 전략은 ETF 일봉이 적합하다. 제한된 자산으로 데이터·주문·리밸런싱을 끝까지 검증할 수 있기 때문이다. 다만 오늘 선택한 ETF 목록도 선택편향이 있으므로 소급 실험과 앞으로의 모의 운용을 구분한다.

## 5. 연구와 운용을 잇는 공통 엔진

**확정 자료 → 지표/신호 → 목표 비중 → 위험 제한 → 주문 계획 → 체결 → 원장·평가**를 공통으로 사용한다.

- 전략 함수는 자료와 현재 포지션·현금으로 목표 비중 및 이유를 반환한다. 브로커 API 호출은 전략 함수에서 하지 않는다.
- 과거 검증은 가상 시계와 체결 시뮬레이터를, 모의 운용은 실제 시간과 모의 체결을 사용한다. 실제 운용은 사용자가 외부에서 수행한 거래를 입력/가져온다. 신호·배분·위험 규칙은 공유하지만 실제 체결은 입력된 기록만 인정한다.
- 백테스트·모의 운용의 기본 체결 가정은 주간/월간 기준일 종가 확정 후 다음 거래일 시가+비용이다. 이는 가정이며 사용자의 실제 체결로 간주하지 않는다. 알림 지연·수동 주문에 따른 1거래일/수거래일 지연과 비용 민감도도 비교한다.
- 매수 가능 현금, 매도 수량, 소수주 지원, 주문 금액 반올림, 잔여 현금, 리밸런싱 임계값을 모델에 포함한다.
- 장중 손절/익절을 일봉 고가·저가만으로 확정 체결하지 않는다. 경로가 불명확하면 보수적 가정과 한계를 표시하거나 세밀한 자료를 요구한다.
- 동일 계좌에서 전략들이 같은 종목을 보유하면 전략별 가상 배분과 계좌 순주문을 분리한다. MVP는 하나의 모의 계좌에 한 전략으로 이 복잡성을 제한한다.

기존 Spring/Python/MySQL/Redis를 유지한다. Python은 전략·계산, Spring은 설정·실행 상태·소유권·원장 API를 담당한다. 실제 운용 작업은 웹 요청과 분리된 제한된 worker로 실행하되, 새 분산 플랫폼부터 도입하지 않는다.

## 6. '좋은 백테스트'를 구분하는 화면

결과 상단은 수익률 한 숫자가 아니라 **자료 품질 / 평가 기간 / 비용 가정 / 검증 구간 / 비교 기준**이다.

- 전략·벤치마크·동일 자산 buy-and-hold를 같은 기준으로 비교한다. CAGR, MDD와 회복 기간, 변동성, Sharpe, 회전율, 거래 비용, 평균 투자 노출, 월별 수익률을 우선 제공한다.
- 개별 거래 손익과 배분형 전략의 성과를 구분한다. 승률은 매매 정의와 거래 수를 함께 보여준다.
- 개발 구간에서 파라미터를 정하고 검증 구간은 시간 순서로 분리한다. 최종 구간은 튜닝에 재사용하지 않는다. 워크포워드는 각 구간에서 이전 자료로만 설정을 정해 이어 붙인다.
- 파라미터 근처에서도 비슷한 결과인지, 수수료·슬리피지를 높여도 유지되는지, 특정 몇 종목/거래에 이익이 몰리는지 비교한다.
- 실험 전체 이력을 저장해 최고 결과만 남기는 편향을 줄인다. 실험 수·선택 사유·검증 구간 재사용 여부를 기록한다.
- 팩터 연구는 자료 확보 후 순위 상관(IC), 분위별 성과, 회전율과 비용을 추가한다. 복잡한 ML·강화학습은 초기 범위에 넣지 않는다.

자료 누락·분할/배당 처리·과거 구성 종목·재무 발표 시점을 충족하지 못한 항목은 '확인 필요'로 표시한다. 검증 통과는 미래 수익 보장이 아니라 다음 단계로 갈 근거다.

## 7. 정기 점검·알림·판단 기록

모의 운용은 과거 백테스트를 매일 다시 실행하는 것과 다르다. 시작 시점을 고정한 계좌에 실제 도착한 데이터로 신호를 생성하고, 이후 체결 및 현금 변화를 누적해야 한다.

자료와 평가는 거래일마다 갱신하되 행동 판단은 선택한 주간/월간 일정에 생성한다. 매 점검마다 자료 확정 여부, 전략 버전, 목표/현재 비중, 조건별 충족 여부, 예상 비용, 유지/변경 검토 결과를 저장한다. 일별 자료 갱신을 매일 거래 알림으로 연결하지 않는다.

사용자 흐름: **이메일/모바일 알림 → 주간 브리핑 또는 월간 검토 → 근거·위험·비중 편차 확인 → 실행/보류/유지와 이유 기록 → 실행했다면 실제 거래 입력 → 다음 점검에서 복기**. 계획 수량은 참고안이며 주문을 전송하지 않는다. '실행 결정'만으로 체결 처리하지 않는다. 백테스트·모의·실제 성과 및 규칙 준수/예외 판단을 분리해 비교한다.

### 알림 정책

- 정기 알림: 주간 브리핑, 월간 리밸런싱 검토. 변화가 없어도 정기 보고에는 '유지·변경 조건 미충족'을 설명한다. 두 일정이 겹치면 하나로 합친다.
- 비정기 알림: 사용자가 설정한 중요한 위험 조건의 새 위반·중대한 변화, 판단을 방해하는 데이터 오류만 발송한다. 임계값 주변 반복 발송을 막는 재알림 간격·회복 조건을 둔다.
- 내용: 변화 요약, 관련 자산, 충족된 규칙과 반대 근거, 현재/목표 비중, 데이터 기준일, 앱의 상세 검토 링크. 제목만으로 매수/매도를 단정하지 않는다.
- 채널: 이메일 및 모바일 웹 푸시를 우선 검토한다. iOS/Android의 설치·권한·백그라운드 수신을 실제 기기로 확인하고 미지원/권한 거절 시 이메일과 앱 알림함을 제공한다. 네이티브 앱은 우선 구축하지 않는다.
- 사용자 설정: 채널 선택, 요일/시각, 시간대, 조용한 시간, 비정기 알림 수신 여부. 이메일 주소·푸시 권한은 사용자가 직접 등록한다. 외부 알림 본문은 기본적으로 잔고·상세 보유 수량을 생략하고 로그인한 앱에서 표시한다.
- 신뢰성: 점검 결과와 발송 대기를 DB에 함께 기록하는 outbox, 결과별 중복 방지 키, 제한된 재시도와 실패 상태를 둔다. 전송 수락·기기 표시·사용자 열람을 동일 상태로 취급하지 않는다.
- 스케줄: 사용자의 Asia/Seoul 알림 시간과 America/New_York 거래일을 분리한다. DST·휴장·월말 마지막 거래일·자료 지연을 반영한다. 자료 미확정이면 행동안을 만들지 않고 점검 지연 사유를 표시한다. 뒤늦게 복구할 때 오래된 행동 알림을 일괄 발송하지 않는다.

자동 주문·브로커 주문 어댑터·강제 청산은 이 계획의 범위에서 제외한다. 실제 거래 연결은 수동 입력 또는 거래 파일 가져오기부터 제공하고 중복 입력·정정·보유/현금 대조를 검증한다.

## 8. 화면·데이터 구조

최상위 화면을 **투자 점검 / 전략 연구 / 포트폴리오 / 데이터·종목**으로 재편한다.

| 화면 | 핵심 표시 |
|---|---|
| 투자 점검 | 주간 시장 브리핑, 월간 비중 검토, 유지/변경 근거, 지난 판단·미처리 항목, 데이터 상태 |
| 전략 연구 | 전략 버전 → 데이터 사전 검사 → 백테스트 → 실험 비교 → 모의 운용 등록 |
| 포트폴리오 | 모의/실제 구분, 현금·비중·성과·낙폭, 벤치마크, 거래·비용·전략 기여 |
| 데이터·종목 | 유니버스, 자료 범위·누락·공급자 상태, 후보 비교와 종목 연구 |

연구/모의/실거래 모드를 제목과 상태로 항상 구분한다. 첫 화면을 다수 지수·옵션 카드로 채우지 않는다. 세부 지표는 전략을 설명하거나 위험을 확인하는 자리에서만 노출한다.

추가 모델 후보: 전략/불변 버전, 데이터 스냅샷, 연구 실행, 점검 일정·결과, 신호·목표 비중, 사용자 판단・이유, 실제/모의 거래 원장·일별 평가, 알림 환경설정·발송 대기/결과. 기존 `backtest_runs`와 포트폴리오를 확장하고 단계별로 필요한 테이블만 추가한다. 점검 결과·사용자 판단·실제 거래를 서로 연결하되 별도 상태로 저장한다.

## 9. 수정된 로드맵과 통과 조건

| 단계 | 산출물 | 다음 단계 조건 |
|---|---|---|
| Q0 기준 구체화 | 주간/월간·수동 판단 방향 확정, 자산 목록·규칙 수치·알림 일정 구체화 | 점검/거래 일정 구분, 유지 조건과 첫 전략을 손으로 계산 가능 |
| Q1 검증 기반 | 기존 계산 오류 수정, 자료 품질 검사, 준비 기간, 체결·현금 엔진 | 경계/누락/비용/기업행사 검산 통과, 입력 버전 고정 시 결과 재현 |
| Q2 투자 점검 MVP | 시장 4축 요약, 첫 ETF 규칙·대조 전략, 주간/월간 검토, 이메일·앱 알림함 | 변화·해석·보유 영향·유지/변경 근거를 확인하고 판단 저장 가능 |
| Q3 검증·모의 운용·모바일 | 실험 비교·시간 순 검증·수동 실행 지연 민감도, 모의 원장, 웹 푸시 | 재시작/자료 지연/중복 스케줄 및 실제 모바일 수신·거부·실패 대안 검증 |
| Q4 실제 기록 연결 | 수동 주문 계획 및 거래 가져오기, 실제/모의 차이 분석 | 브로커 거래·현금·보유와 대조 가능, 중복 가져오기 없음 |
| Q5 판단 복기 | 규칙 준수/예외 판단, 보류·실행 지연, 실제/모의 성과·비용 비교 | 과거 판단 당시 근거를 재조회하고 차이 원인을 확인 가능 |
| Q6 전략 확대 | 주식 팩터·다중 전략·동적 배분 | 과거 시점 자료, 전략별 귀속·합산 위험과 선택편향 평가 준비 |

**최초 완료 목표:** 주간/월간 알림을 받고 → 시장 상황과 내 규칙의 변화를 이해하고 → 근거 있는 실행/보류/유지 결정을 기록하는 전체 흐름. 전략 개수나 알림 수보다 실제 판단에 도움이 되는지를 우선한다.

### 제품 성공 기준

- 주간/월간 검토를 5~10분 안에 마치고 '무엇이 변했고 왜 유지/변경하는가'를 사용자가 설명할 수 있는지 확인한다. 목표이며 아직 측정한 결과는 아니다.
- 모든 판단에 규칙 버전·자료 시점·조건별 근거가 연결되고, 자료 부족을 '유지 신호'로 바꾸지 않는다.
- 정기 보고의 유지 결과, 월말/주말 중복 억제, DST·휴장·수집 지연, 발송 실패·재시도를 검사한다. 같은 결과를 재처리해도 새 알림이 중복 생성되지 않아야 한다.
- 과거 검토를 수정된 최신 자료로 덮어쓰지 않고 당시 판단과 실제 행동을 복기할 수 있다.

모의 운용 관찰 기간은 거래 빈도에 맞춰 정한다. 예를 들어 월별 전략의 한 달 무사 실행은 전략 유효성 검증에 충분하지 않다. 운영 신뢰성과 투자 성과 평가는 다른 통과 조건으로 관리한다.

## 10. 현재 범위에서 제외

장중 단타·자동 주문·레버리지·공매도·옵션 거래·복잡한 ML 전략·네이티브 모바일 앱은 현재 로드맵에서 제외한다. 기존 실시간 시세는 참고 기능으로 유지하되 주간/월간 판단은 확정된 자료로 생성한다. 이메일/푸시 서비스와 알림 일정의 실제 등록·발송은 구현 및 사용자 설정 이후이며, 이번 작업은 계획 갱신이다.
