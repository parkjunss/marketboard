01프로젝트 개요

라즈베리파이(8GB RAM, 1TB SSD) 위에서 Docker Compose로 구동되는 미국 주식 실시간 모니터링 웹 애플리케이션을 개발한다. 백엔드는 Java(Spring Boot), 실시간 시세는 Finnhub 무료 WebSocket 스트림을 사용하며, 회원은 일반 유저와 관리자로 구분한다. 모니터링(Prometheus + Grafana)과 CI/CD(GitHub Actions)까지 포함해 수집 → 저장 → 실시간 전달 → 시각화 → 배포의 전체 사이클을 직접 구축하는 것이 목표다.

핵심 목표

  • Finnhub WebSocket(무료, 최대 50심볼)으로 비용 0원 실시간 시세 확보
  • JWT 기반 인증/인가 — ROLE_USER / ROLE_ADMIN 권한 분리 및 관리자 페이지
  • Redis 캐시 + Pub/Sub를 활용한 실시간 브로드캐스트 구조
  • 틱 데이터를 1분봉(OHLCV)으로 집계해 자체 히스토리 축적
  • ARM64 크로스빌드 기반 GitHub Actions 자동 배포 파이프라인

비목표 (이번 범위에서 제외)

  • 실제 주문/매매 기능 (모니터링 전용)
  • 한국 주식 실시간 시세 (확장 아이디어로 이관 — §09)
  • 모바일 네이티브 앱 (반응형 웹으로 대체)

요청 흐름은 두 갈래다. ① 사용자 트래픽은 Nginx가 정적 프론트엔드를 서빙하고 /api는 REST로, /ws는 WebSocket 업그레이드로 백엔드에 프록시한다. ② 시세 트래픽은 Python 수집기가 Finnhub 스트림을 받아 Redis에 캐시·발행하고, 백엔드가 이를 구독해 STOMP 토픽으로 클라이언트에 푸시한다. 두 흐름이 Redis에서 만나는 구조라 유저 수가 늘어도 외부 API 사용량은 일정하다.

04데이터 파이프라인 설계

실시간 경로 (장중)

  • 구독 — 수집기가 wss://ws.finnhub.io에 연결, 관리자가 등록한 심볼(최대 50개) 구독. 재접속·하트비트·지수 백오프 필수
  • 스로틀링 — 활발한 종목은 초당 수십 틱이 들어오므로 종목별 초당 1회로 다운샘플링 후 Redis Pub/Sub(quotes 채널) 발행
  • 캐시 — 최신가는 quote:{symbol} 키로 Redis에 상시 유지 (신규 접속자 초기 렌더링용)
  • 브로드캐스트 — 백엔드가 Redis 구독 → STOMP /topic/quotes/{symbol}로 클라이언트 푸시
  • 집계 — 수집기가 틱을 모아 1분봉(OHLCV) 생성, 분 마감 시 MySQL price_history에 저장

보조 경로

  • REST 폴백 (장외) — 거래가 없으면 틱도 없으므로, 장 마감 시간대엔 Finnhub REST /quote로 마지막 스냅샷 표시 (60 req/min 한도 내 여유)
  • 히스토리 백필 — 신규 종목 등록 시 yfinance로 과거 일봉을 일괄 수집해 차트 공백 제거
  • 소스 추상화 — 수집기 내부를 QuoteSource 인터페이스로 추상화해 향후 소스 교체/추가 대비
CONSTRAINT Finnhub 무료 티어: WebSocket 동시 구독 50심볼, REST 60콜/분, 미국 주식 위주. 무료 조건은 변동 가능하므로 가입 후 대시보드에서 실제 한도 확인 필요. 미국 정규장은 한국 시간 밤 10:30~새벽 5:00(서머타임 기준) — 실시간 기능 테스트는 이 시간대에 진행.

05기능 구현 범위

공통 / 인증

  • 회원가입 · 로그인 · 로그아웃 (Access Token 15분 + Refresh Token은 Redis 저장, 강제 만료 가능)
  • Spring Security 필터 체인에서 JWT 검증, @PreAuthorize로 엔드포인트별 권한 통제
  • WebSocket 핸드셰이크 시에도 JWT 검증 (STOMP CONNECT 인터셉터)

일반 유저 (ROLE_USER)

  • 실시간 시세 보드 — 구독 종목의 현재가·등락률·거래량 실시간 갱신, 상승/하락 색상 플래시
  • 개인 워치리스트 — 전체 추적 종목 중 관심 종목 선택·정렬, 종목별 상세 페이지
  • 차트 — lightweight-charts 기반 캔들차트 (1분봉 실시간 + 일봉 히스토리)
  • 가격 알림 — 목표가 도달 시 알림 (조건은 Redis 캐시, 수집기가 틱마다 체크 → WebSocket 알림 푸시)

관리자 (ROLE_ADMIN)

  • 추적 종목 관리 — 50개 구독 슬롯의 추가/삭제/우선순위 관리, 변경 시 수집기에 실시간 반영
  • 유저 관리 — 목록 조회, 권한 변경, 계정 정지, 리프레시 토큰 강제 만료
  • 수집기 상태 모니터 — WS 연결 상태, 종목별 마지막 틱 시각, 재접속 횟수, REST 쿼터 사용량
  • 시스템 현황 — 접속자 수, WebSocket 세션 수, 최근 에러 로그 요약

06데이터 모델 초안

테이블주요 컬럼비고
usersid, email, password_hash, role, status, created_atrole: USER / ADMIN, status로 정지 처리
symbolsid, ticker, name, exchange, is_active, priority관리자가 관리하는 구독 화이트리스트 (≤50 active)
watchlist_itemsid, user_id, symbol_id, sort_order유저별 관심 종목
price_historysymbol_id, ts, open, high, low, close, volume, timeframe1분봉 + 일봉, (symbol_id, timeframe, ts) 복합 인덱스
alertsid, user_id, symbol_id, condition, target_price, triggered_at활성 조건은 Redis에 미러링

틱 원본은 MySQL에 저장하지 않는다(볼륨 과다). 실시간 값은 Redis, 영속 데이터는 봉 단위로만 저장하는 것이 원칙. Redis 키 설계: quote:{symbol}(최신가 Hash), refresh:{userId}(토큰), alerts:{symbol}(활성 알림 조건 Set).

07개발 로드맵

각 페이즈는 단독으로 동작하는 결과물을 완료 조건으로 삼는다. 예상 기간은 퇴근 후/주말 작업 기준의 대략치.

P1

기반 공사 — Compose 뼈대 + 인증

예상 1~2주 · docker-compose · Spring Security · JWT
  • docker-compose.yml 작성: mysql, redis, backend 3개 컨테이너 기동 (ARM64 이미지 확인)
  • Spring Boot 프로젝트 셋업, Flyway 마이그레이션으로 users 테이블 생성
  • 회원가입/로그인 API, JWT 발급·검증, Refresh Token Redis 저장·재발급·로그아웃
  • ROLE_USER / ROLE_ADMIN 분리, 테스트용 관리자 시드 계정
DONE WHENcurl로 가입→로그인→토큰 재발급→권한별 엔드포인트 접근 제어가 전부 동작
P2

데이터 수집기 — Finnhub 연동

예상 1~2주 · Python · WebSocket 클라이언트 · Redis
  • Finnhub WSS 연결, 심볼 구독, 재접속(지수 백오프) + 핑/퐁 처리
  • 틱 스로틀링(종목당 초당 1회) 후 Redis 캐시 갱신 + Pub/Sub 발행
  • 1분봉 집계기 구현, 분 마감 시 MySQL 저장
  • yfinance 일봉 백필 스크립트, 장외 시간 REST /quote 폴백
  • FastAPI로 헬스체크·구독 목록 갱신용 내부 API 노출
DONE WHEN미국 장중에 redis-cli로 실시간 가격 갱신이 보이고, MySQL에 1분봉이 쌓임
P3

실시간 전달 — 백엔드 WebSocket

예상 1주 · STOMP · Redis Pub/Sub 브리지
  • STOMP over SockJS 엔드포인트 구성, CONNECT 시 JWT 검증 인터셉터
  • Redis 구독 → /topic/quotes/{symbol} 브로드캐스트 브리지
  • 시세 조회 REST API (Redis 캐시 우선, 히스토리는 MySQL)
  • 워치리스트 CRUD API
DONE WHEN웹소켓 테스트 클라이언트로 구독하면 실시간 시세가 푸시됨
P4

프론트엔드 — 시세 보드와 차트

P5

  • 추적 종목 관리 UI — 등록/삭제가 수집기 구독에 즉시 반영 (내부 API 호출)
  • 유저 관리: 목록·권한 변경·정지·토큰 강제 만료

P6

관측성 — Prometheus + Grafana

예상 1주 · Actuator · 커스텀 메트릭
  • 백엔드 Actuator + Micrometer 노출, Prometheus 스크레이핑 설정
  • 수집기 커스텀 메트릭: 초당 틱 수, 재접속 횟수, REST 쿼터 사용량, 집계 지연
  • Grafana 대시보드: JVM/컨테이너 리소스, 수집 파이프라인 상태, WS 세션 수
  • 임계치 알림 룰 (수집기 연결 끊김, 디스크 사용량 등)
DONE WHENGrafana에서 전체 파이프라인 상태를 한눈에 확인 가능
P7

CI/CD — GitHub Actions

예상 1주 · buildx ARM64 · GHCR · 자동 배포
  • PR 시 테스트 실행 워크플로 (백엔드 단위 테스트, 프론트 빌드 검증)
  • main 머지 시 docker buildx로 ARM64 이미지 빌드 → GHCR 푸시
  • 배포: SSH 스텝으로 Pi에서 docker compose pull && up -d (또는 Watchtower)
  • 시크릿 관리: Finnhub 키, DB 비밀번호 등은 GitHub Secrets + .env 주입
DONE WHENmain에 푸시하면 몇 분 뒤 Pi에서 새 버전이 자동으로 떠 있음

08운영·인프라 유의사항

  • ARM64 이미지 — 모든 베이스 이미지 멀티아치 확인. Java는 eclipse-temurin 사용, QEMU 크로스빌드는 자바 빌드가 느릴 수 있으므로 캐시 레이어 적극 활용
  • 메모리 상한 — 컨테이너별 mem_limit 명시로 특정 서비스 폭주 시 전체 다운 방지
  • TLS — 외부 공개 시 Nginx에 Let's Encrypt(certbot) 적용, WSS 필수
  • 백업 — MySQL 덤프 cron(일 1회) + Grafana/Prometheus 볼륨은 별도 디렉토리로 분리
  • 시간대 — 서버·DB·집계 전부 UTC 통일, 표시만 KST/EST 변환 (봉 집계 버그의 최다 원인)
  • 보안 — Finnhub 키는 수집기 컨테이너에만 주입, 프론트에 절대 노출 금지. 관리자 API는 rate limit 적용

09이후 확장 아이디어

  • 한국 주식 — KIS(한국투자증권) 오픈API 무료 실시간 웹소켓 연동, QuoteSource 추상화 덕에 수집기에 소스 추가만으로 확장
  • 알림 채널 확장 — 텔레그램 봇 / 이메일 알림
  • 포트폴리오 트래킹 — 가상 보유 수량 입력 → 평가손익 실시간 계산
